RINCLE SEO設定ガイド

初心者向け -- 専門知識ゼロから始められます

SEOって何？

ひとことで言えば「Googleで検索したとき、自分のサイトをできるだけ上に表示させるための工夫」です。
検索結果で上のほうに出れば、お金をかけなくても多くの人にサイトを見てもらえます。

!
RINCLEの現状
Googleにインデックス（登録）されているページはわずか2ページ。
「スポーツバイク レンタル」「ロードバイク レンタル 神戸」「スポーツバイク 試乗」など主要キーワードで検索圏外です。
つまり、検索からの流入がほぼゼロの状態です。

なぜこうなっているのか

RINCLEはBubble.io（ノーコードツール）で作られています。Bubble.ioで作ったサイトは、普通のサイトとHTMLの構造が異なり、Googleが内容を理解しにくいという問題があります。

|
Googleが内容を理解できる
X
RINCLE（現状）
|
HTMLがほぼ空っぽ。JavaScriptで後から描画するためGoogleに情報が伝わらない
|

Bubble.ioでも設定できる項目はあります。以下の5ステップで、できる限りの対策を行いましょう。

やるべきこと 5ステップ

上から順番に取り組んでください。Step 1が最も重要です。

メタ情報の設定 最重要

検索結果に表示される情報や、SNSでシェアされたときの見え方を設定します。

titleタグ（タイトルタグ）

何？ ブラウザのタブに表示される文字であり、Google検索結果の青い文字のリンク部分です。

文字数: 30〜60文字が目安。長すぎると「...」で切れます。

ポイント: ページの内容を端的に表し、狙いたいキーワードを前半に入れる。

ページtitle 設定例
トップページスポーツバイクをレンタル・試乗するならRINCLE｜全国のプロショップで安心体験
店舗一覧店舗一覧｜RINCLE - スポーツバイクレンタル
店舗詳細スペシャライズド神戸｜ロードバイク・E-Bikeレンタル｜RINCLE
車種一覧レンタルできる車種一覧｜RINCLE - スポーツバイクレンタル
料金料金プラン｜RINCLE - スポーツバイクレンタル
はじめての方へはじめての方へ｜RINCLEの使い方ガイド

Bubble.ioでの設定方法:
各ページのエディタを開き、左上の「Page」メニュー → 「SEO / metatags」タブ → 「Page title」欄に入力します。動的な値を入れたい場合は「Insert dynamic data」を使います。

meta description（メタ ディスクリプション）

何？ Google検索結果でタイトルの下に表示されるグレーの説明文です。

文字数: 70〜120文字が目安。

ポイント: ユーザーが「このページを見たい」と思うような説明を書く。キーワードを自然に含める。

ページmeta description 設定例
トップページ全国24店舗のプロショップでロードバイク・E-Bikeをレンタル。プロの整備で安心、ネットで簡単予約。初めてのスポーツバイク体験にも最適です。

Bubble.ioでの設定方法:
titleタグと同じ「SEO / metatags」タブ内の「Meta description」欄に入力します。

OGP（Open Graph Protocol）

何？ LINE・X（旧Twitter）・FacebookなどでURLを送ったときに表示されるカード（画像+タイトル+説明）の設定です。

設定項目:

  • og:title -- カードのタイトル（titleタグと同じでOK）
  • og:description -- カードの説明文（meta descriptionと同じでOK）
  • og:image -- カードの画像（推奨: 1200 x 630px）
  • og:url -- ページのURL

Bubble.ioでの設定方法:
「SEO / metatags」タブ内にOGP用の入力欄（「OG Title」「OG Description」「OG Image」）があります。それぞれ入力してください。

h1タグ（大見出し）

何？ そのページで一番大きな見出し。Googleは「このページは何について書かれているか」をh1タグから判断します。

ポイント: 各ページに1つだけ設定する。titleタグと似た内容でOK。

Bubble.ioでの設定方法:
ページ内の一番重要なテキスト要素を選択 → 右パネルの「HTML tag」から「H1」を選択します。各ページに1つだけH1を設定してください。

alt属性（画像の説明テキスト）

何？ 画像が表示されなかったときに代わりに表示されるテキスト。Googleの画像認識の手がかりにもなります。

ポイント: 「IMG_0234.jpg」のようなファイル名ではなく、「ロードバイクのレンタル車体イメージ」のように内容を説明する。

Bubble.ioでの設定方法:
画像要素を選択 → プロパティ内の「Describe the image for accessibility」欄にテキストを入力します。

canonical URL（正式URLの指定）

何？ 同じ内容のページが複数のURLで表示される場合に、「正式なURLはこれです」とGoogleに伝える仕組みです。重複ページの評価分散を防ぎます。

例: https://rincle.co.jp/top と https://rincle.co.jp/top?param=xxx が同じ内容なら、前者をcanonicalに指定。

Bubble.ioでの設定方法:
「SEO / metatags」タブ内の「Canonical URL」欄にそのページの正式なURLを入力します。全ページに設定することを推奨します。

sitemapの作成

sitemap（サイトマップ）とは、サイトの全ページの一覧を記した「地図」です。Googleに「うちのサイトにはこんなページがありますよ」と教えるためのファイルです。

sitemapに登録するURL一覧

サイト内の全ページのURLを登録する。

静的ページ（固定）
11
トップ/一覧/FAQ/料金/登録 等
店舗詳細（動的）
24+
店舗数に応じて増加
車種詳細（動的）
N件
車種数に応じて増加
例: 店舗100 + 車種200の場合 → 静的11 + 店舗100 + 車種200 = 合計311 URL を全部sitemapに登録する。
店舗や車種が増えるたびに手動で追加するのは現実的ではないので、Bubble.ioプラグインで自動生成が推奨。

各タグの意味

タグ 意味 設定例
<loc>ページのURLhttps://rincle.co.jp/shop_detail/specialized-kobe
<changefreq>更新頻度のヒントdaily / weekly / monthly / yearly
<priority>サイト内での重要度（0.0〜1.0）トップ=1.0、店舗=0.8、規約=0.2

robots.txt への追記

robots.txt はGoogleのクローラー（情報収集ロボット）に指示を出すファイルです。ここにsitemapの場所を書いておくと、Googleが自動で読み取ってくれます。

User-agent: *
Allow: /

Sitemap: https://rincle.co.jp/sitemap.xml

Bubble.ioでの設定方法:
Settings → 「SEO / metatags」 → 下のほうにある「robots.txt」欄に上記内容を貼り付けます。サイトマップはBubble.ioが自動生成するものを使うか、手動でXMLファイルを用意してホスティングします。

Google Search Console 登録

Google Search Console（サーチコンソール）は、Googleが提供する無料ツールです。サイトがGoogleにどう見えているかを確認・管理できます。

1
Search ConsoleにGoogleアカウントでログイン
2
「プロパティを追加」から「URLプレフィックス」を選び、https://rincle.co.jpを入力
3
所有権の確認方法で「HTMLタグ」を選択し、表示されたmetaタグをコピー
4
Bubble.io Settings → SEO / metatags →「Script in header」にmetaタグを貼り付けて保存
5
Search Consoleに戻り「確認」ボタンをクリック。「所有権を確認しました」が出ればOK
+
登録後、左メニューの「サイトマップ」からStep 2で作ったsitemapのURLを送信しましょう。

GA4（Googleアナリティクス）導入

GA4は、サイトに何人来て、どのページを見て、どれくらい滞在したかを計測する無料ツールです。

導入手順

  1. Googleアナリティクスにログイン → 「管理」 → 「プロパティを作成」
  2. プロパティ名（例: RINCLE）、タイムゾーン（日本）、通貨（日本円）を設定
  3. データストリーム → 「ウェブ」を選択 → URLに https://rincle.co.jp を入力
  4. 表示された測定ID（G-XXXXXXXXXX）をコピー
  5. 以下のコードをBubble.ioの「Script in header」に貼り付け

設置コード例

<!-- Google tag (gtag.js) -->
<script async src="https://www.googletagmanager.com/gtag/js?id=G-XXXXXXXXXX"></script>
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag(){dataLayer.push(arguments);}
  gtag('js', new Date());
  gtag('config', 'G-XXXXXXXXXX');
</script>

※ G-XXXXXXXXXX の部分を実際の測定IDに置き換えてください。

Microsoft Clarity（クラリティ）の導入

ユーザーの画面操作を録画・可視化する無料ツール

クラリティとは

Microsoftが無料で提供する、ユーザーがサイト上でどう動いているかを録画・可視化するツール。
GA4が「何人来て、どのページを見たか」の数字を教えてくれるのに対し、クラリティは「どこをクリックし、どこで迷っているか」を映像で見せてくれる。

GA4だけの場合
「予約フローで60%が離脱している」
→ 分かるけど「なぜ」は分からない
GA4 + クラリティの場合
「60%が離脱」（GA4）
→ 録画で「料金が見つからず戻っている」（クラリティ）
→ 「料金を明示すれば改善」と判断できる

主な機能

🎥 セッション録画
ユーザーの画面操作を動画で再生。「ここで迷ってる」が一目で分かる
🔥 ヒートマップ
ページのどこがよくクリックされているか、どこまでスクロールされているかを色で可視化
👆 デッドクリック検出
クリックしても何も起きなかった箇所を自動検出（= UIが分かりにくい箇所）
😤 レイジクリック検出
同じ場所を何度もクリックした箇所を検出（= 反応が遅い or 動かないと思われた箇所）

導入手順

1. アカウント作成
https://clarity.microsoft.com/ にアクセス → Microsoft/Google/Facebookアカウントでログイン → New project → URL: https://rincle.co.jp

2. Bubble.ioに設置
表示されるスニペットをコピーし、Bubble.io の Settings > SEO/metatags > Script/meta tags in header に貼り付け（GA4スニペットの下に追加）

3. 動作確認
別ブラウザでrincle.co.jpにアクセスして操作 → 数分後にクラリティのダッシュボードに録画が表示されればOK

GA4 との使い分け

知りたいこと GA4 クラリティ
何人来たか、どこから来たか●-
どのページで離脱しているか（数字）●-
なぜ離脱しているか（映像）-●
どこがクリックされているか-●
広告の効果測定●-
UIの改善ポイント発見-●
両方とも完全無料。 GA4で「どこで」離脱しているかを数字で把握し、クラリティで「なぜ」離脱しているかを映像で確認する。

効果測定

設定して終わりではありません。定期的にチェックして改善を続けましょう。

1週間後にチェックすること

  • Search Consoleでインデックス登録されたページ数が増えているか
  • GA4でデータが取れているか（リアルタイムレポートで確認）
  • Search Consoleにエラーが出ていないか
  • OGPが正しく表示されるか（LINEやXにURLを貼って確認）

2〜4週間後にチェックすること

  • Search Consoleの「検索パフォーマンス」で表示回数・クリック数を確認
  • 狙ったキーワードで検索順位が付き始めているか
  • GA4で自然検索（Organic Search）からの流入が発生しているか
  • ページごとのtitle・descriptionに改善の余地がないか見直す
  • 新しいページを追加したらsitemapを更新し、再送信する

SEO設定チェックリスト

全項目にチェックが入れば、基本的なSEO対策は完了です。

Step 1: メタ情報

  • 全ページにtitleタグを設定した（30〜60文字）
  • 全ページにmeta descriptionを設定した（70〜120文字）
  • 全ページにOGP（og:title, og:description, og:image）を設定した
  • 各ページにh1タグを1つ設定した
  • 主要な画像にalt属性を設定した
  • 全ページにcanonical URLを設定した

Step 2: サイトマップ

  • XMLサイトマップを作成した
  • robots.txtにサイトマップのURLを記載した

Step 3: Search Console

  • Google Search Consoleにサイトを登録した
  • 所有権の確認が完了した
  • サイトマップをSearch Consoleから送信した

Step 4: GA4

  • GA4のプロパティを作成した
  • 測定コードをサイトに設置した
  • リアルタイムレポートでデータ取得を確認した

Step 4.5: Microsoft Clarity

  • Clarityのアカウントを作成し、プロジェクトを追加した
  • スニペットをBubble.ioのheaderに設置した
  • ダッシュボードで録画データの取得を確認した

Step 5: 効果測定

  • 1週間後チェックの日をカレンダーに登録した
  • インデックス数の増加を確認した
  • 検索パフォーマンス（表示回数・クリック数）を定期確認する体制を作った
