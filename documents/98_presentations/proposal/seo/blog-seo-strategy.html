検索評価はどこに貯まるか
noteで貯めたSEO評価は後から自社ドメインに移せません（無料版noteにリダイレクト機能がなく、評価はnote.comに帰属したまま）。「まずnoteで始めて育ったら自社へ引っ越す」は、引っ越しの瞬間に検索評価がゼロリセットされます。
推奨は「移行」ではなく「最初から分業併用」。

noteの実態（なぜ自社が必要か）

03

どの形式で — LP vs ブログ記事

集客と刈り取りの2段構え
SEOで集客するなら「ブログ記事 ＋ 本体サイトのエリアページ」。 狭義のLP（縦長1ページ・CV特化）はSEO目的では作りません。

狭義LPがSEOに弱い理由：①CV特化ページは被リンクがつきにくい ②1ページではKWを網羅できず薄い ③情報収集の検索意図に記事形式が優位

※ ただし作り込んだ複数ページのLPなら別。中身が情報性を持ち複数ページに分かれていれば、それは実質ブログ / オウンドメディアと同じ（呼び名の差）。弱いのは「ペラ1枚の売り込み」。

「ブログ記事 ＋ 本体エリアページ」とは

2種類のページはユーザーの段階が違う。「本体エリアページ」は新規に作る別物ではなく、rincle.co.jpの予約サイト側にある既存のエリア検索 / 店舗一覧ページ（sitemap化する約430URL〈店舗56・自転車374ほか静的ページ・2026-08-20本番実測〉）を指す。

① ブログ記事② 本体エリアページ
置き場所自社ブログ基盤（新設・当面サブドメインの静的LP。6月30日更新）rincle.co.jp 予約サイト側（既存・Bubble）
例「神戸の海沿いサイクリングコース完全ガイド」「神戸 ロードバイクレンタル（店舗一覧・予約）」
見ている人情報収集段階（まだ借りると決めてない）もう借りる気で探している（取引型）
役割集客（検索で広く拾う）→ 記事内リンクで②へ予約の刈り取り（ここでCV）
 
導線のイメージ

検索「神戸 サイクリングコース」（どこ走ろう）
  → ① ブログ記事「神戸の海沿いコースガイド」      ← 集客（網を広げる）
    → 記事内リンク「このコースを走るなら →」
      → ② 本体エリアページ「神戸 ロードバイクレンタル」 ← 予約（刈り取り）

検索「ロードバイク レンタル 神戸」（もう借りたい）
  → ② 本体エリアページに直接着地 → 予約

何のツールで — WordPress vs Bubble vs note

6月19日時点の比較として保存（WordPressは保留中）
6月30日更新: WordPressは保留し、当面はClaude Code製の静的LPで自走することになりました（§0）。本節は6月19日時点の比較として残します — WordPress vs BubbleのSEO比較は引き続き有効で、WordPressは記事運用が本格化した時（量産が回り始めた・代行に切り替える等）の選択肢です。

CMSはWordPress（→ 6月30日より保留・本格化時の選択肢）

先方（増永さん側）が自分で記事を書く方針のため、最も馴染みやすい管理画面（WYSIWYG・見たまま編集）と自走しやすさを優先（IT知識が浅い・非エンジニアでも書ける / 詰まっても日本語の解説・情報量が最多）。

項目内容
月額レンタルサーバー 600〜1,100円程度（エックスサーバー693円〜・ConoHa WING 660円〜）
初期費用ほぼゼロ（有料テーマを買う場合のみ1〜2.5万円）
保守中 更新・バックアップ・セキュリティ対応が継続発生 → 弊社が準委任で対応（先方の負担なし）
表示速度動的生成のため素のままだと重め → キャッシュ等で実用域に上げる
  • rincle.co.jpはBubbleホスティングのため、WordPress用サーバーは別途新規契約（純増コスト）。Bubble上にWordPressは載せられないので、§6のCloudflare Workerでサブディレクトリに同居させます。

WordPress vs BubbleのCMS記事（Bubbleで十分か？）

SEOの強さは WordPress ＞ BubbleのCMS。ただしBubbleでも出せる（インデックスはされる）＝程度問題。 タイトル / descを可変にしても、「重さ（表示速度）」と「本文がJSでしか出ない」の2つは記事ページでも残る。

SEO要素WordPressBubbleのCMS記事
title / description（可変）◎ 自動○ 手動だが可能
表示速度（Core Web Vitals）○〜◎× Bubble本体はLCP49秒の実測・記事も遅い
本文・見出し（h1 / h2）の構造◎△ JSレンダリングで初期HTMLに乗りにくい
JS依存のインデックス◎ HTML即提供△ 描画はされるが遅延・取りこぼし
構造化データ / canonical / sitemap◎ 自動△ 弱い・手動
内部リンク（クロール）◎ HTML出力△ JS生成でクロールされにくい
立ち上げ工数・コストサーバー＋構築◎ 既存Bubble内で完結・追加ほぼゼロ

→ 本気でSEO上位を取りに行く記事はWordPress。お知らせ・低競合ならBubbleで十分（次節）。

05

用途で振り分け

狙いとKWの性質で置き場所を変える

「全部WordPress」でも「全部Bubble」でもない。狙いとKWの性質で置き場所を変える。

コンテンツ置き場所理由
本命のSEO資産
（主要都市・観光ルートのコース記事）		作り込んだ静的LP記事（自社サブドメイン・6月30日更新。本格化時はWordPress）上位を取りに行く＝速度・構造が要る（静的HTMLは両方満たす）
店舗の地点 × レンタル（取引型KW）Bubble本体の店舗 / エリアページをSEO最適化§3の通り受け皿は本体ページ。記事を作るまでもない
加盟店の「お知らせレベル」発信
（6月19日要望→6月30日この方向で合意）		BubbleのCMS（Bubble内にCMSを実装）SEOは二の次・手軽さ優先。ニッチKWならBubbleのSEOでも足りる
運営の想い・ストーリー・拡散note（無料）検索資産にする必要がないもの

「低競合」とは（具体例）

  • 指名・ブランド系：「RINCLE ◯◯店」「リンクル レンタル ◯◯」
  • 超ローカル×ニッチ：「△△駅 ロードバイク レンタル」「◯◯川サイクリングロード レンタル 初心者」
  • 絞り込みロングテール：「ロードバイク レンタル 1日 手ぶら ◯◯」

逆に高競合（＝WordPressで本気を出す主戦場）：「ロードバイク レンタル 東京 / 大阪 / 名古屋」「しまなみ海道 レンタサイクル」。

イベント発信は低競合？ → 2種類に分かれる

競合だけでなく"検索需要"も見るのがポイント。

① 自店の小さいイベント告知（「◯◯店 ナイトライド 6月30日」）→ 低競合だが低需要・時限的。SEO資産にならない＝Bubbleのお知らせで十分

② 大型イベント便乗（「大阪城トライアスロン レンタル」＝6月19日で実際に流入）→ 中需要。イベント名に検索需要があるので拾える＝記事 or 広告＋LPで取りに行く

地名の粒度で取り方が変わる

細かい地名（店舗のある地点）＝低競合＝Bubbleでも最悪上位は取れる。ただし注意3つ：①競合と一緒に検索需要も下がる（取れても流入わずか）②速度ハンデは常にある（"勝てるだけ"で理想ではない）③分散すると内部リンク・クラスタの相乗効果が切れる（増えるならWordPressに集約）。

KWの粒度競合取り方
主要都市・観光大型KW（情報型）高静的LP記事（本命・6月30日更新。本格化時はWordPress）
店舗の地点 × レンタル（取引型）低Bubble本体ページをSEO最適化。記事を作るまでもない
細かい地点 × コース情報（需要あれば）低数が少なければBubble可。増えるなら静的LP / WordPress側に集約

実現方式・始め方（6月30日更新）

サブディレクトリ vs サブドメイン・SEO差の洗い出し結果

サブディレクトリ vs サブドメイン — 当面はサブドメインで開始

サブディレクトリ（rincle.co.jp/blog/）サブドメイン（例: lp.rincle.co.jp）
SEO◎ rincle.co.jp本体にドメイン評価を集約できる△ 評価はサブドメイン側に貯まる（本体への波及は限定的）
実現方式リバースプロキシが必須（Cloudflare WorkerでURLごとにWordPress / Bubbleへ出し分け）DNSにレコードを1本足すだけ。本体と完全に独立
リスク× 落ちるとブログもアプリ本体も全滅（単一障害点）。弊社にBubble×WordPressでの運用実績がなく、障害時の原因切り分けも難しい○ 本体に影響なし（LP側が落ちてもアプリは無事）
  • 6月30日定例の結論: 安全側のサブドメインで開始。どうしても本体のドメインパワーを上げたい場合はリスクを承知の上でサブディレクトリ対応も可能、という整理
  • 宿題（弊社）は7月2日に調査完了 → 結果は次項。差は小さく、後から移行もできるため、サブドメイン継続を推奨
  • サブディレクトリを採用する場合の技術詳細をまとめた実装手順書（blog-implementation-guide.md）は2026-08-25に削除（当面サブドメイン方針のため。必要になったらgit履歴から復元できる）。DNSがA / AAAAレコードだとWorkerがバイパスされる報告があるため、採用時はrincle.co.jpのDNS構成の技術検証が必要

SEO差の洗い出し結果（2026-07-02調査・6月30日宿題の回答）

結論: SEO差は「ゼロとは言い切れないが、RINCLEの規模では小さい」。しかも後から301リダイレクトで検索評価を引き継いでサブディレクトリへ移行できるため、サブドメインで始めても取り返しがつきます。当面サブドメイン継続を推奨します。

① Google公式は「どちらでも同等」を一貫して明言

  • GoogleのJohn Mueller氏が2016年・2017年・2018年・2021年と繰り返し「サブドメインとサブディレクトリは本質的に同等。どちらに置いても構わない」と公式に発言
  • サブドメイン特有の手間は「Googleがクロールの仕方を別途学習する」ことだが、最初の数日で終わるプロセスで順位への影響はない
  • ただし留保が1つ：Googleは「どこまでが1つのサイトか」を自動判定しており、サブドメインを本体と同一サイトとみなす場合と、別サイトとみなす場合の両方がある。どちらに判定されるかは運営側で確実にはコントロールできない

② SEO実務家側は「サブディレクトリ優位」を主張（ただし証拠の質は一段落ちる）

  • Moz創業者Rand Fishkin氏らは「サブドメイン→サブディレクトリ移行でトラフィックが増えた」事例（HotPads・Salesforce等）を根拠にサブディレクトリ優位を主張し続けている
  • 一方で海外SEO情報ブログの鈴木謙一氏は「サブディレクトリ化そのものではなく、移行に付随した他の変更がプラスに働いたと考えるのが自然」と指摘 — 移行事例は因果関係が証明されていない
  • 「正しく運用すればサブドメインで成功している例は多数ある」という実務家の反論や、Google関係者の「ビジネスと技術リソースの制約で選ぶのが正解」という見解もある
  • RINCLEへの補足：仮に実務家の主張が正しくても、差が効くのは本体とブログが同一サイト評価される場合。rincle.co.jp本体は予約アプリ（Bubble）で記事メディアとは性質が違うため、サブディレクトリに置いても同一サイト評価の恩恵が確実に得られる保証はない

③ 後からの移行は可能（＝今サブドメインを選んでも詰まない）

  • Google公式ドキュメントが「301等の恒久リダイレクトでPageRank（リンク評価）は失われない」と明言
  • 移行の反映は中規模サイトで数週間。記事数十本規模ならさらに短い。移行中の順位変動は一時的なもので、時間とともに安定する（Google公式）
  • 注意：Mueller氏は「長く維持できる構成を選ぶべき」とも発言 — 頻繁な引っ越しはNG。「サブドメインで開始→本格化したら1回だけ移行」までは現実的な範囲
判断材料内容
SEO差Google公式は「同等」。実務家の「サブディレクトリ優位」は因果未証明で、立ち上げ期（記事数十本）に効く差とは考えにくい
リスク差サブディレクトリはリバースプロキシ（単一障害点・弊社運用実績なし）が必須。サブドメインはDNS1本で本体に影響なし
可逆性サブドメイン→サブディレクトリは301リダイレクトで評価を引き継いで移行可能（＝保険がある）
結論当面サブドメイン継続。ブログが本格化して（目安: 記事50本超）ドメイン集約の価値が障害リスクを上回ったら、その時点で移行を再検討

始め方と順序

  1. 前提：DB再構築・本番リリースは完了済み（2026年7月上旬）。次はSEO基盤一式（メタ情報・sitemap・Search Console・GA4）の整備で、基盤構築は準委任で対応
  2. 記事（静的LP）は増永さん側がClaude Codeで作成して自走。量産は一瞬でできるが、AIの文章のまま公開すると検索順位が上がりにくいため公開前の手直しが必須。弊社はKW選定・ペルソナ選定を支援
  3. 公開先はサブドメイン（LPが増えることを見越してlp.等の汎用名を推奨）。rincle.co.jp本体とペダルスタンダードHPの両方からリンクを張り、検索流入と併走。noteは即日開始できる
  4. 優先KW：最優先「観光ルート名×レンタサイクル」（しまなみ海道・ビワイチ等）、次点「都市名×ロードバイク レンタル」。「スポーツバイク」軸は使わない
  5. 1本目は加盟店が実在し実走できる地域（例: 神戸）から。記事テンプレ1種（コース概要・マップ・立ち寄りスポット・レンタル導線）を設計して量産
