SEOって何？

現状と期待効果

ひとことで言えば「Googleで検索したとき、自分のサイトをできるだけ上に表示させるための工夫」です。
検索結果で上のほうに出れば、お金をかけなくても多くの人にサイトを見てもらえます。

RINCLEの現状（2026-06-11実測で更新）
Googleにインデックス（登録）されているページは実質2〜3ページのみ。
（1）トップページ（2）店舗詳細1件 -- しかも日付・検索条件のクエリパラメータ付きのままインデックス（3）規約ページ
「スポーツバイク レンタル」「ロードバイク レンタル 神戸」など主要キーワードで検索圏外。
つまり、今のRINCLEはGoogleから見てほぼ存在していない状態です。正確なインデックス数はSearch Console導入後に確認します。

02

なぜこうなっているのか（2026-06-11実測で更新）

実際のHTMLを取得して確認した結果

RINCLEはBubble.io（ノーコードツール）で作られています。Bubble.ioで作ったサイトは「中身（本文）がJavaScriptで後から読み込まれる」構造になっています。
2026-06-11に実際のHTMLを取得して確認した結果は以下のとおりです。

O意外と設定されていたもの

サーバー側でHTMLに出力済み:
・titleタグ（店舗詳細では店舗名入りの動的タイトルまで生成されている）
・meta description / OGP一式

X問題が残っているもの

・本文がHTMLにほぼ無い: トップの可視テキストは「Rincle」の6文字だけ。店舗詳細でも31文字（タイトルの重複のみ）。料金・車種・住所・営業時間はゼロ
・初期HTMLにh1/h2が一切ない
・ページ間の<a>リンクが初期HTMLに無い（リンクはJS生成のみ）
・sitemap.xmlが404 / robots.txtにSitemap行なし
・canonicalなし → 検索条件付きのゴミURLが「正式なページ」としてインデックスされる実害が発生中
・meta descriptionは全ページ同一文面、og:imageはアイコン画像の流用（品質課題）

重要な補足: 「Bubble（JSレンダリング）だからインデックスされない」は正確ではありません。 Vercel×MERJの大規模調査（Googlebotのフェッチ10万件以上を分析）では、GoogleはCSRページを含むHTML 200ページの100%をフルレンダリングしており、レンダリング待ちも中央値10秒程度でした（出典: Vercel調査 / Google公式 JavaScript SEO解説）。
RINCLEのインデックスが2〜3ページに留まっている主因は、sitemapが無い + 内部リンクがJS生成のみ → Googleがページを発見できない「ディスカバリーの問題」である可能性が高い。つまり、このガイドのStep 1〜3（メタ情報・sitemap・Search Console）という基本の整備だけでも大きく改善する余地があります。

メタ情報の設定 canonicalは実害確認済み・早急に

検索結果に表示される情報や、SNSでシェアされたときの見え方を設定します。

titleタグ（タイトルタグ）

何？ ブラウザのタブに表示される文字であり、Google検索結果の青い文字のリンク部分です。

文字数: 30〜60文字が目安。長すぎると「...」で切れます。

ポイント: ページの内容を端的に表し、狙いたいキーワードを前半に入れる。検索キーワードは「ロードバイク」「E-Bike」軸を使い、「スポーツバイク」は使わない（サジェスト調査で誰も検索しないことを確認済み・社名やブランド説明の文中はOK。詳細は「検索キーワード調査」資料）。全ページに「RINCLE」を含め、ページごとに違うタイトルにする。

RINCLEの現状（2026-06-11実測）: 設定済みだが品質が低い。トップは Rincle の6文字だけでキーワードが無く、店舗詳細は Rincle｜RINCLE 箕面稲店 / スペシャライズド箕面 と動的生成はできているが「レンタル」等の検索キーワードが入っていない。

Bubble.ioでの設定方法:
対象のページを選択 → 左メニュー「Appearance」 → 「Page title」欄に入力します。動的な値を入れたい場合は「Insert dynamic data」を使います。

meta description（メタ ディスクリプション）

何？ Google検索結果でタイトルの下に表示されるグレーの説明文です。

文字数: 70〜120文字が目安。

ポイント: そのページに何が書いてあるかを具体的に書き、「全国54店舗」「プロショップ」等の差別化ポイントと行動を促す言葉（「簡単予約」等）を入れる（店舗数は2026-06-11時点のDB実数。対外表記は「全国100店舗以上」で決め打ちする方向で協議中〈6/19・#33〉→ 確定後に全ページの文言を差し替える）。

RINCLEの現状（2026-06-11実測）: 設定済み。ただし全ページ同一文面（店舗詳細ページもトップと同じ説明文）。ページごとに固有の文面へ差し替えるのが課題。

ページmeta description 設定例
トップページ全国54店舗のプロショップでロードバイク・E-Bikeをレンタル。プロの整備で安心、ネットで簡単予約。初めてのスポーツバイク体験にも最適です。
店舗一覧RINCLEのパートナーショップを検索。全国54店舗から、最寄りの店舗を見つけてロードバイク・E-Bikeをレンタルできます。
店舗詳細（例: 神戸）スペシャライズド神戸でロードバイク・E-Bikeをレンタル。JR神戸駅から徒歩3分。プロスタッフが初心者にも丁寧にサポートします。

Bubble.ioでの設定方法:
対象のページを選択 → 「Appearance」 → 「Meta description」欄に入力します。

OGP（Open Graph Protocol）

何？ LINE・X（旧Twitter）・FacebookなどでURLを送ったときに表示されるカード（画像+タイトル+説明）の設定です。

RINCLEの現状（2026-06-11実測）: og:title / og:description / og:image / og:url / og:type / og:site_name すべて設定済み。ただしog:imageがアプリアイコン（apple-touch-icon.png）の流用で、推奨の1200×630pxサイズでない。SNSカードの見栄えのため専用画像への差し替えが課題。

設定項目:

  • og:title -- カードのタイトル（titleタグと同じでOK）
  • og:description -- カードの説明文（meta descriptionと同じでOK）
  • og:image -- RINCLEのロゴ or 自転車の写真（推奨: 1200 x 630px）
  • og:url -- そのページのURL
  • og:type -- website
  • og:site_name -- RINCLE

Bubble.ioでの設定方法:
対象ページの「Appearance」設定内の「SEO / metatags」セクションで設定します。または Settings > SEO/metatags > Script/meta tags in header にHTMLで直接記述します。

h1タグ（大見出し）

何？ そのページで一番大きな見出し。Googleは「このページは何について書かれているか」をh1タグから判断します。

RINCLEの現状（2026-06-11実測）: 初期HTMLにh1/h2が一切ない（Googleがページのテーマを判断できない）。

ポイント: 各ページに1つだけ設定する。ページのメインテーマを表し、検索キーワードを自然に含める。

Bubble.ioでの設定方法:
テキスト要素を選択 → 「Appearance」 → 「HTML tag」を「H1」に変更します。各ページに1つだけH1を設定してください。

alt属性（画像の説明テキスト）

何？ 画像が表示されなかったときに代わりに表示されるテキスト。Googleの画像認識の手がかりにもなります。

RINCLEの現状: alt属性がほぼ設定されていない。

ポイント: 「IMG_0234.jpg」のようなファイル名ではなく、「Specialized Allez E5 Disc ロードバイク」「スペシャライズド神戸 店舗外観」のように内容を説明する。

Bubble.ioでの設定方法:
画像要素を選択 → プロパティ内の「Describe the image for accessibility」欄にテキストを入力します。

canonical URL（正式URLの指定）

何？ 同じ内容のページが複数のURLで表示される場合に、「正式なURLはこれです」とGoogleに伝える仕組みです。重複ページの評価分散を防ぎます。

例: https://rincle.co.jp/shop_detail?shop=12345 と https://rincle.co.jp/shop_detail?shop=12345&ref=top が同じ内容なら、前者をcanonicalに指定。

RINCLEの現状（2026-06-11実測）: canonicalが無いため、日付・検索条件のクエリパラメータが付いたままのURLが「店舗ページの正式な姿」としてインデックスされている実害が確認済み。早急に設定すべき。

Bubble.ioでの設定方法（2026-06-11更新: ネイティブ機能で対応可能）:
Bubbleには標準でcanonical出力機能があり、手書きHTMLは不要です。Settings > SEO/metatags の「Enable canonical url」のチェックボックスをONにします（説明文に "Check this box to enable a Bubble-defined canonical url tag." とある。2026-06-11にBubble公式マニュアルで名称を確認済み。参考: Bubble公式マニュアル）。

noindex（検索結果に出さないページの設定）

何？ 「このページはGoogleの検索結果に載せないで」と伝えるタグです。マイページ・予約履歴一覧のようなログイン後の個人情報ページ（noindex必須）や、ログイン・予約・パスワード再設定・加盟店申込・管理画面のような検索から来ても意味がない機能ページ（noindex推奨）に設定します。店舗詳細・自転車詳細などそれ以外のページはSEOの入口なので何もしません。

  • 2026-08-20更新: DB再構築後の新ページ構成に合わせて対象を差し替え（旧: mypage / login / register / reserve）。

Bubble.ioでの設定方法:
エディタで対象ページ（mypage / user_reservation_list / signin / reservation / reset_pw / shop_form / admin系4ページ）を開く → ページの何もない部分をダブルクリック → 「Page HTML Header」欄に <meta name="robots" content="noindex"> を貼り付けます。

注意: Settings > SEO/metatags > Script/meta tags in header（GA4スニペットを貼った場所）には絶対に貼らないでください。あちらは全ページ共通のヘッダーなので、noindexを書くとサイト全体がGoogleから消えます。noindexは必ずページごとのPage HTML Headerに設定します。

あわせて確認（2026-06-11更新）: 以前のBubbleには「Allow search engines to index this app」というアプリ全体のインデックス許可チェックがありましたが、現在の公式マニュアルにはこの項目の記載がなく、画面に表示されないという報告もあります。見当たらなくても探し回らなくてOK（本番アプリは標準でインデックス許可されます）。代わりに次の2点を確認: （1）公開ページのソースに意図しないnoindexが入っていないか（2）robots.txtでサイト全体をブロックしていないか（現状のrobots.txtは/version-test/のみDisallowなので問題なし）。

確認方法: 公開ページで右クリック →「ページのソースを表示」で、noindex対象ページにだけタグが入っていればOK。Search Console導入済みなら「URL検査」で「インデックス登録: 許可されていません（noindex）」と表示されます。なお、noindexにするページはsitemapには載せません（「登録して」と「登録しないで」が矛盾するため）。

構造化データ（JSON-LD）新規追加

何？ 「このページは自転車店の情報です」「これは商品で価格は6,000円です」と、Googleが機械的に理解できる形式（JSON-LD）でページに埋め込むデータ。検索結果に星評価・パンくず・FAQ等の「リッチリザルト」が表示される条件になります。

RINCLEの現状（2026-06-11実測）: 構造化データなし。

スキーマ適用ページ備考
BikeStore（LocalBusinessのサブタイプ）各店舗詳細schema.orgに自転車店専用タイプがある。name / address / geo / openingHours / priceRange を設定。Googleのローカルビジネス・リッチリザルト対象
Product + Offer各車種詳細レンタル価格を offers.price に。レビュー獲得後は AggregateRating を追加すると★表示が狙える（現状レビューゼロのため当面は価格のみ）
BreadcrumbList全ページ検索結果のパンくず表示
FAQPageよくある質問リッチリザルト対象
Organizationトップロゴ・SNSプロフィールの紐付け
  • 「レンタル専用」のリッチリザルトはGoogleに存在しないため、上記の組み合わせで対応します。

Bubble.ioでの設定方法:
各ページの「Page HTML Header」に <script type="application/ld+json">...</script> を記述（動的データの差し込み可）。設定後はリッチリザルトテストで検証します。

sitemapの作成

sitemap（サイトマップ）とは、サイトの全ページの一覧を記した「地図」です。Googleに「うちのサイトにはこんなページがありますよ」と教えるためのファイルです。

各タグの意味

タグ意味設定例
<loc>ページのURLhttps://rincle.co.jp/shop_detail?shop=<店舗ID>
<changefreq>更新頻度のヒントdaily / weekly / monthly / yearly
<priority>サイト内での重要度（0.0〜1.0）トップ=1.0、店舗=0.8、規約=0.2

XMLサイトマップの例

<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <!-- 静的ページ -->
  <url>
    <loc>https://rincle.co.jp/</loc>
    <changefreq>weekly</changefreq>
    <priority>1.0</priority>
  </url>
  <url>
    <loc>https://rincle.co.jp/search</loc>
    <changefreq>daily</changefreq>
    <priority>0.9</priority>
  </url>

  <!-- 動的ページ: 店舗詳細（全店舗分） -->
  <url>
    <loc>https://rincle.co.jp/shop_detail?shop=1784194786574x498131851707290800</loc>
    <changefreq>weekly</changefreq>
    <priority>0.8</priority>
  </url>
  <!-- ... 残りの店舗も同様 ... -->

  <!-- 動的ページ: 自転車詳細（全台数分） -->
  <url>
    <loc>https://rincle.co.jp/bicycle_detail?bicycle=1767680741415x960023914326261800</loc>
    <changefreq>weekly</changefreq>
    <priority>0.7</priority>
  </url>
  <!-- ... 残りの自転車も同様 ... -->
</urlset>

robots.txt への追記

robots.txt はGoogleのクローラー（情報収集ロボット）に指示を出すファイルです。ここにsitemapの場所を書いておくと、Googleが自動で読み取ってくれます。

RINCLEの現状: sitemapの場所が書かれていない。

User-agent: *
Disallow: /version-test/

追記すべき内容:

User-agent: *
Disallow: /version-test/
Sitemap: https://rincle.co.jp/sitemap.xml

Bubble.ioでの設定方法（2026-06-11更新）:
Settings > SEO/metatags の「Customize robots.txt (advanced)」のチェックボックスをONにし、表示された編集欄に上記を入力します。

Google Search Console 登録

Google Search Console（サーチコンソール）は、Googleが提供する無料ツールです。サイトがGoogleにどう見えているかを確認・管理できます。

  1. Search ConsoleにGoogleアカウントでログイン
  2. 「プロパティを追加」から「URLプレフィックス」を選び、https://rincle.co.jpを入力
  3. 所有権の確認方法で「HTMLタグ」を選択し、表示されたmetaタグをコピー
  4. Bubble.io Settings → SEO / metatags →「Script in header」にmetaタグを貼り付けて保存
  5. Search Consoleに戻り「確認」ボタンをクリック。「所有権を確認しました」が出ればOK
  6. 「URL検査」でトップ・検索ページ・主要な店舗詳細のインデックス登録をリクエスト
登録後、左メニューの「サイトマップ」からStep 2のsitemap（sitemap.xml）を送信しましょう。1〜2週間後に「カバレッジ」（インデックス数）・「検索パフォーマンス」（表示キーワード）・「エラー」を確認します。

GA4（Googleアナリティクス）導入

GA4は、サイトに何人来て、どのページを見て、どれくらい滞在したかを計測する無料ツールです。

実例（2026-06-11追記）: 2026年2月にアクセスが普段の約1.5倍（3,402PV / 1,603IP）に急増しましたが、アクセスログでは参照元が分からず要因を特定できませんでした。GA4が入っていれば「集客 > トラフィック獲得」レポートで、どこから来た急増なのか一目で分かります。
進捗（2026-07-02追記）: GA4アカウントは増永さん側で作成済み（計測資産はクライアント所有・弊社も招待済み）。6/29の確認で開発版URL（/version-xxx/）が本番と別ページとして二重カウントされていることが分かったため、GAタグの読み込みを本番（live）バージョンのみに限定する対応を行います（タスク#44）。

導入手順

  1. Googleアナリティクスにログイン → 「管理」 → 「プロパティを作成」
  2. プロパティ名（例: RINCLE）、タイムゾーン（日本）、通貨（日本円）を設定
  3. データストリーム → 「ウェブ」を選択 → URLに https://rincle.co.jp を入力
  4. 表示された測定ID（G-XXXXXXXXXX）をコピー
  5. 以下のコードをBubble.ioの「Script in header」に貼り付け

設置コード例

<!-- Google tag (gtag.js) -->
<script async src="https://www.googletagmanager.com/gtag/js?id=G-XXXXXXXXXX"></script>
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag(){dataLayer.push(arguments);}
  gtag('js', new Date());
  gtag('config', 'G-XXXXXXXXXX');
</script>
  • G-XXXXXXXXXX の部分を実際の測定IDに置き換えてください。

Microsoft Clarity（クラリティ）の導入

ユーザーの画面操作を録画・可視化する無料ツール

クラリティとは

Microsoftが無料で提供する、ユーザーがサイト上でどう動いているかを録画・可視化するツール。
GA4が「何人来て、どのページを見たか」の数字を教えてくれるのに対し、クラリティは「どこをクリックし、どこで迷っているか」を映像で見せてくれる。

GA4だけの場合
「予約フローで60%が離脱している」
→ 分かるけど「なぜ」は分からない
GA4 + クラリティの場合
「60%が離脱」（GA4）
→ 録画で「料金が見つからず戻っている」（クラリティ）
→ 「料金を明示すれば改善」と判断できる

主な機能

セッション録画
ユーザーの画面操作を動画で再生。「ここで迷ってる」が一目で分かる
ヒートマップ
ページのどこがよくクリックされているか、どこまでスクロールされているかを色で可視化
デッドクリック検出
クリックしても何も起きなかった箇所を自動検出（= UIが分かりにくい箇所）
レイジクリック検出
同じ場所を何度もクリックした箇所を検出（= 反応が遅い or 動かないと思われた箇所）

https://clarity.microsoft.com/ にアクセス → Microsoft/Google/Facebookアカウントでログイン → New project → URL: https://rincle.co.jp

2. Bubble.ioに設置
表示されるスニペットをコピーし、Bubble.io の Settings > SEO/metatags > Script/meta tags in header に貼り付け（GA4スニペットの下に追加）

3. 動作確認
別ブラウザでrincle.co.jpにアクセスして操作 → 数分後にクラリティのダッシュボードに録画が表示されればOK

知りたいことGA4クラリティ

両方とも完全無料。 GA4で「どこで」離脱しているかを数字で把握し、クラリティで「なぜ」離脱しているかを映像で確認する。

効果測定

設定して終わりではありません。定期的にチェックして改善を続けましょう。

1週間後にチェックすること

  • Search Consoleでインデックス登録されたページ数が増えているか
  • GA4でデータが取れているか（リアルタイムレポートで確認）
  • Search Consoleにエラーが出ていないか
  • OGPが正しく表示されるか（LINEやXにURLを貼って確認）

2〜4週間後にチェックすること

  • Search Console「ページ（カバレッジ）」でインデックス数が増えたか（2〜3ページ → 主要ページ分に増加が期待値）
  • Search Consoleの「検索パフォーマンス」で表示回数・クリック数を確認
  • 狙ったキーワードで検索順位が付き始めているか
  • GA4で自然検索（Organic Search）からの流入が発生しているか
  • ページごとのtitle・descriptionに改善の余地がないか見直す
  • サイトの表示速度をPageSpeed Insightsで確認（LCP 2.5秒以下が理想）

プリレンダリング（Prerender.io）の導入（2026-06-11更新）

Step 1〜3を完遂してもインデックスが伸びない場合の次の一手。クローラーにだけ、JSレンダリング済みの完全なHTML（本文・リンク入り）を返す仕組み。

  • 方式: Cloudflare Workerをドメインのフロントに置き、ボットのリクエストだけPrerenderへルーティングする公式手順がある（人間のアクセスは従来どおりBubbleへ）

  • 料金（2025年10月改定 / 2026-06-11に公式料金ページで再確認済み）: 無料プランは2025年10月15日に廃止。現在はStarter $49/月（25,000レンダー）〜、Growth $149/月（100,000レンダー）。30日間の無料トライアルあり
  • 注意: 改善するのはクローラーから見えるHTMLだけで、人間のユーザーの表示速度は1ミリ秒も変わらない

SEO設定チェックリスト

全項目にチェックが入れば基本のSEO対策は完了

全項目にチェックが入れば、基本的なSEO対策は完了です。

Step 1: メタ情報

  • 全ページのtitleタグをキーワード入りの固有の文面に修正した（現状: 設定済みだがトップは「Rincle」のみ）
  • 全ページのmeta descriptionをページ固有の文面に修正した（現状: 全ページ同一文面）
  • og:imageを1200×630の専用画像に差し替えた（現状: アイコン流用）
  • 各ページにh1タグを設定した
  • 画像にalt属性を設定した
  • 「Enable canonical url」のチェックボックスをONにした（Bubble-defined canonical url tagが出力される）
  • 主要ページに構造化データ（BikeStore / Product+Offer / BreadcrumbList / FAQPage）を設定し、リッチリザルトテストで検証した
  • noindex対象ページ（マイページ/予約履歴一覧/ログイン・会員登録/予約/パスワード再設定/加盟店申込/管理画面4ページ）のPage HTML Headerにnoindexを設定した
  • index対象ページにnoindexが入っていないことを確認した
  • アプリ全体がインデックス可能なことを確認した（公開ページのソースに意図しないnoindexが無い・robots.txtで全体をブロックしていない。2026-06-11更新）

Step 2: sitemap / robots.txt

  • Data APIで shop / Bicycle を公開にチェックし、本番デプロイした（「sitemap.xml 作成手順」手順2）
  • generate_sitemap.js でsitemap.xmlを生成し、店舗数・自転車数がサイトの実数と合っていることを確認した
  • 「Hosting files in the root directory」でsitemap.xmlをアップロードした（自動生成「Expose a sitemap file」はOFFのまま）
  • https://rincle.co.jp/sitemap.xml でアクセスできることを確認した
  • robots.txtに「Sitemap: https://rincle.co.jp/sitemap.xml」を追記した

Step 3: Search Console

  • Google Search Consoleにプロパティを追加した
  • サイトの所有権を確認した
  • sitemapを送信した
  • 主要ページのインデックス登録をリクエストした

Step 4: GA4

  • GA4アカウントを作成した
  • 測定ID（G-XXXXXXXXXX）を取得した
  • Bubble.ioのheaderにGA4スニペットを貼り付けた
  • リアルタイムレポートで動作確認した

Step 4.5: Microsoft Clarity

  • クラリティのアカウントを作成した
  • トラッキングコードを取得した
  • Bubble.ioのheaderにクラリティのスニペットを貼り付けた
  • ダッシュボードでセッション録画が表示されることを確認した

Step 5: 効果測定

  • 1週間後: GA4とSearch Consoleが動作していることを確認
  • 2〜4週間後: インデックス数の増加と検索キーワードの出現を確認

このガイドに出てくる用語の意味

用語意味
SEOSearch Engine Optimization の略。検索エンジンで上位表示するための施策全般。
インデックスGoogleがページの情報をデータベースに登録すること。インデックスされないと検索結果に出ない。
クローラーGoogleがウェブを巡回してページ情報を集める自動プログラム（ロボット）。
titleタグブラウザのタブと検索結果の青文字リンクに使われるページタイトル。
meta description検索結果でタイトル下に表示されるグレーの説明文。クリック率に影響する。
OGPOpen Graph Protocol。SNSでURLを共有したときに表示されるカードの設定。
h1タグページの大見出し。そのページのテーマをGoogleに伝える役割。
alt属性画像の代替テキスト。画像が表示できないときやGoogleの画像理解に使われる。
canonical URL複数URLで同じ内容がある場合に「正式なURL」を指定するタグ。
noindex「このページは検索結果に載せないで」とGoogleに伝えるタグ。マイページ等の検索に出すべきでないページに設定する。

robots.txtクローラーに対して「見てよい/見ないでほしい」ページを指示するファイル。
Search ConsoleGoogle提供の無料ツール。検索結果での見え方やエラーを確認・管理できる。
GA4Google Analytics 4。サイト訪問者の行動を計測する無料のアクセス解析ツール。
Microsoft ClarityMicrosoftが無料で提供するユーザー行動分析ツール。セッション録画やヒートマップで「なぜ離脱するか」を映像で確認できる。
セッション録画ユーザーがサイト上でどう操作したかを動画として記録・再生する機能。
ヒートマップページのどこがよくクリックされているか、どこまでスクロールされているかを色（赤=多い/青=少ない）で可視化したもの。
デッドクリックユーザーがクリックしたけど何も反応しなかった箇所。UIが分かりにくい証拠。
LCPLargest Contentful Paint。ページの一番大きな要素が表示されるまでの時間。
CVRConversion Rate。サイトに来た人のうち、予約まで完了した人の割合。
プリレンダリングJSで動的に表示されるページを、事前にHTMLとして生成しておく技術。SEO対策に有効。
オーガニック検索広告でなく自然な検索結果からのアクセスのこと。SEOで増やすのはこの流入。

コンバージョンサイト上で達成してほしい目標行動（例: レンタル予約の完了）。
