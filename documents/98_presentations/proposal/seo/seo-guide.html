SEOって何？

現状と期待効果・なぜ今やるか

ひとことで言えば「Googleで検索したとき、自分のサイトをできるだけ上に表示させるための工夫」です。
検索結果で上のほうに出れば、お金をかけなくても多くの人にサイトを見てもらえます。

RINCLEの現状（2026-06-11実測で更新）
Googleにインデックス（登録）されているページは実質2〜3ページのみ。
（1）トップページ（2）店舗詳細1件 — しかも日付・検索条件のクエリパラメータ付きのままインデックス（3）規約ページ
「スポーツバイク レンタル」「ロードバイク レンタル 神戸」など主要キーワードで検索圏外。
つまり、今のRINCLEはGoogleから見てほぼ存在していない状態です。正確なインデックス数はSearch Console導入後に確認します。

なぜ今SEOをやるのか — 数字で見る期待効果（2026-06-11 本番アクセスログ実測）

GA4が未設置のため、サーバーのアクセスログから実測した現状:

月間アクセス 約700IP 約2,300 PV / 月
予約CVR 約4% 来訪者の約4%が予約完了。健全な水準です
予約1件の売上 ≒ ¥1,530 平均予約単価 ¥10,200 × 手数料15%
検索流入 +100人 / 月なら +6,100円 / 月 予約 +4件 / 月。広告費ゼロで、設定すれば効き続けます
CVR約4%は「サイトに来てもらえさえすれば、ちゃんと予約につながっている」という意味。つまり今のボトルネックは流入で、検索からの流入を増やせば予約はほぼ比例して増える見込みが立ちます。
ちなみに2026年2月に3,402PV / 1,603IPへのスパイクがありました。要因は特定できていません（アクセスログでは参照元まで分からない）。GA4を導入すれば（Step 4）、こうした急増がどこから来たのか（SNSで紹介された？メディアに載った？）が分かるようになります。

検索結果とSNSでの見え方を整える

検索結果に表示される情報や、SNSでシェアされたときの見え方を設定します。まず、いま何がどうなっているかの一覧です。

項目いまの状態（2026-06-11実測）
titleタグ設定済みだが品質が低い。トップは Rincle の6文字だけでキーワードが無い
meta description設定済み。ただし全ページ同一文面
OGP設定済み。ただし og:image がアプリアイコンの流用で、推奨の1200×630pxでない
h1タグ初期HTMLに h1 / h2 が一切ない
alt属性ほぼ設定されていない
canonical URL未設定。クエリパラメータ付きのURLが店舗ページの正式な姿としてインデックスされる実害を確認済み（早急に対応）
構造化データなし

titleタグ（タイトルタグ）

何？ ブラウザのタブに表示される文字です。Google検索結果の青い文字のリンク部分でもあります。

文字数: 30〜60文字が目安。長すぎると「...」で切れます。

ポイント: ページの内容を端的に表す。狙いたいキーワードを前半に入れる。検索キーワードは「ロードバイク」「E-Bike」軸を使い、「スポーツバイク」は使わない（サジェスト調査で誰も検索しないことを確認済み・社名やブランド説明の文中はOK。詳細は「検索キーワード調査」資料）。全ページに「RINCLE」を含め、ページごとに違うタイトルにする。

RINCLEの現状（2026-06-11実測）: 設定済みだが品質が低い。トップは Rincle の6文字だけでキーワードが無く、店舗詳細は Rincle｜RINCLE 箕面稲店 / スペシャライズド箕面 と動的生成はできているが「レンタル」等の検索キーワードが入っていない。

Bubble.ioでの設定方法

  1. 対象のページを選択する
  2. 左メニューの「Appearance」 > 「Page title」欄に入力する
  3. 動的な値を入れたい場合は「Insert dynamic data」を使う

meta description（メタ ディスクリプション）

何？ Google検索結果でタイトルの下に表示されるグレーの説明文です。

文字数: 70〜120文字が目安。

ポイント: そのページに何が書いてあるかを具体的に書き、「全国54店舗」「プロショップ」等の差別化ポイントと行動を促す言葉（「簡単予約」等）を入れる（店舗数は2026-06-11時点のDB実数。対外表記は「全国100店舗以上」で決め打ちする方向で協議中〈6月19日・#33〉→ 確定後に全ページの文言を差し替える）。

RINCLEの現状（2026-06-11実測）: 設定済み。ただし全ページ同一文面（店舗詳細ページもトップと同じ説明文）。ページごとに固有の文面へ差し替えるのが課題。

ページmeta description 設定例
トップページ全国54店舗のプロショップでロードバイク・E-Bikeをレンタル。プロの整備で安心、ネットで簡単予約。初めてのスポーツバイク体験にも最適です。
店舗一覧RINCLEのパートナーショップを検索。全国54店舗から、最寄りの店舗を見つけてロードバイク・E-Bikeをレンタルできます。
店舗詳細（例: 神戸）スペシャライズド神戸でロードバイク・E-Bikeをレンタル。JR神戸駅から徒歩3分。プロスタッフが初心者にも丁寧にサポートします。

Bubble.ioでの設定方法

  1. 対象のページを選択する
  2. 「Appearance」 > 「Meta description」欄に入力する

OGP（Open Graph Protocol）

何？ LINE・X（旧Twitter）・FacebookなどでURLを送ったときに表示されるカード（画像+タイトル+説明）の設定です。

RINCLEの現状（2026-06-11実測）: og:title / og:description / og:image / og:url / og:type / og:site_name すべて設定済み。ただしog:imageがアプリアイコン（apple-touch-icon.png）の流用で、推奨の1200×630pxサイズでない。SNSカードの見栄えのため専用画像への差し替えが課題。

設定項目:

  • og:title — カードのタイトル（titleタグと同じでOK）
  • og:description — カードの説明文（meta descriptionと同じでOK）
  • og:image — RINCLEのロゴ or 自転車の写真（推奨: 1200×630px）
  • og:url — そのページのURL
  • og:type — website
  • og:site_name — RINCLE

Bubble.ioでの設定方法

  1. 対象ページの「Appearance」 > 「SEO / metatags」で設定する
  2. または Settings > SEO / metatags > Script / meta tags in header にHTMLで直接記述する

h1タグ（大見出し）

何？ そのページで一番大きな見出し。Googleは「このページは何について書かれているか」をh1タグから判断します。

RINCLEの現状（2026-06-11実測）: 初期HTMLにh1 / h2が一切ない（Googleがページのテーマを判断できない）。

ポイント: 各ページに1つだけ設定する。ページのメインテーマを表す。検索キーワードを自然に含める。

Bubble.ioでの設定方法

  1. テキスト要素を選択する
  2. 「Appearance」 > 「HTML tag」を「H1」に変更する
  3. 各ページにH1が1つだけになっていることを確かめる

alt属性（画像の説明テキスト）

何？ 画像が表示されなかったときに代わりに表示されるテキスト。Googleの画像認識の手がかりにもなります。

RINCLEの現状: alt属性がほぼ設定されていない。

ポイント: 「IMG_0234.jpg」のようなファイル名ではなく、「Specialized Allez E5 Disc ロードバイク」「スペシャライズド神戸 店舗外観」のように内容を説明する。

Bubble.ioでの設定方法

  1. 画像要素を選択する
  2. プロパティの「Describe the image for accessibility」欄にテキストを入力する

canonical URL（正式URLの指定）

何？ 同じ内容のページが複数のURLで表示される場合に、「正式なURLはこれです」とGoogleに伝える仕組みです。重複ページの評価分散を防ぎます。

例: https://rincle.co.jp/shop_detail?shop=12345 と https://rincle.co.jp/shop_detail?shop=12345&ref=top が同じ内容なら、前者をcanonicalに指定。

RINCLEの現状（2026-06-11実測）: canonicalが無いため、日付・検索条件のクエリパラメータが付いたままのURLが「店舗ページの正式な姿」としてインデックスされている実害が確認済み。早急に設定すべき。

Bubble.ioでの設定方法（標準機能で対応できるため、手書きHTMLは不要です）

  1. Settings > SEO / metatags を開く
  2. 「Enable canonical url」のチェックボックスをONにする（説明文に "Check this box to enable a Bubble-defined canonical url tag." とある）
  • 参考: Bubble公式マニュアル

noindex（検索結果に出さないページの設定）

何？ 「このページはGoogleの検索結果に載せないで」と伝えるタグです。マイページ・予約履歴一覧のようなログイン後の個人情報ページ（noindex必須）や、ログイン・予約・パスワード再設定・加盟店申込・管理画面のような検索から来ても意味がない機能ページ（noindex推奨）に設定します。店舗詳細・自転車詳細などそれ以外のページはSEOの入口なので何もしません。

  • 2026-08-20更新: DB再構築後の新ページ構成に合わせて対象を差し替え（旧: mypage / login / register / reserve）。

Bubble.ioでの設定方法

  1. エディタで対象ページ（mypage / user_reservation_list / signin / reservation / reset_pw / shop_form / admin系4ページ）を開く
  2. ページの何もない部分をダブルクリックする
  3. 「Page HTML Header」欄に <meta name="robots" content="noindex"> を貼り付ける
注意: Settings > SEO / metatags > Script / meta tags in header（GA4スニペットを貼った場所）には絶対に貼らないでください。あちらは全ページ共通のヘッダーなので、noindexを書くとサイト全体がGoogleから消えます。noindexは必ずページごとのPage HTML Headerに設定します。

あわせて確認すること

  • 公開ページのソースに、意図しない noindex が入っていないか
  • robots.txtでサイト全体をブロックしていないか（現状は /version-test/ のみDisallowなので問題なし）

確認方法: 公開ページで右クリック →「ページのソースを表示」で、noindex対象ページにだけタグが入っていればOK。Search Console導入済みなら「URL検査」で「インデックス登録: 許可されていません（noindex）」と表示されます。なお、noindexにするページはsitemapには載せません（「登録して」と「登録しないで」が矛盾するため）。

構造化データ（JSON-LD）新規追加

何？ 「このページは自転車店の情報です」「これは商品で価格は6,000円です」と、Googleが機械的に理解できる形式（JSON-LD）でページに埋め込むデータ。検索結果に星評価・パンくず・FAQ等の「リッチリザルト」が表示される条件になります。

RINCLEの現状（2026-06-11実測）: 構造化データなし。

スキーマ適用ページ備考
BikeStore（LocalBusinessのサブタイプ）各店舗詳細schema.orgに自転車店専用タイプがある。name / address / geo / openingHours / priceRange を設定。Googleのローカルビジネス・リッチリザルト対象
Product + Offer各車種詳細レンタル価格を offers.price に。レビュー獲得後は AggregateRating を追加すると星表示（リッチリザルト）が狙える（現状レビューゼロのため当面は価格のみ）
BreadcrumbList全ページ検索結果のパンくず表示
FAQPageよくある質問リッチリザルト対象
Organizationトップロゴ・SNSプロフィールの紐付け
  • 「レンタル専用」のリッチリザルトはGoogleに存在しないため、上記の組み合わせで対応します。

Bubble.ioでの設定方法

  1. 各ページの「Page HTML Header」に <script type="application/ld+json">...</script> を記述する（動的データの差し込みができる）
  2. 設定後にリッチリザルトテストで検証する

Step 2. sitemapの作成

ページ一覧をGoogleに知らせる

sitemap（サイトマップ）とは、サイトの全ページの一覧を記した「地図」です。Googleに「うちのサイトにはこんなページがありますよ」と教えるためのファイルです。

この章の読み方: sitemapは弊社が手動で生成してBubbleに配置します。作り方の詳細は「sitemap.xml 作成手順」にあります。

各タグの意味

タグ意味設定例
<loc>ページのURLhttps://rincle.co.jp/shop_detail?shop=<店舗ID>
<changefreq>更新頻度のヒントdaily / weekly / monthly / yearly
<priority>サイト内での重要度（0.0〜1.0）トップ=1.0、店舗=0.8、規約=0.2

XMLサイトマップの例

<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <!-- 静的ページ -->
  <url>
    <loc>https://rincle.co.jp/</loc>
    <changefreq>weekly</changefreq>
    <priority>1.0</priority>
  </url>
  <!-- ... 残りの静的ページも同様 ... -->

  <!-- 動的ページ: 店舗詳細（全店舗分） -->
  <url>
    <loc>https://rincle.co.jp/shop_detail?shop=1784194786574x498131851707290800</loc>
    <changefreq>weekly</changefreq>
    <priority>0.8</priority>
  </url>
  <!-- ... 残りの店舗も同様 ... -->

  <!-- 動的ページ: 自転車詳細（全台数分） -->
  <url>
    <loc>https://rincle.co.jp/bicycle_detail?bicycle=1767680741415x960023914326261800</loc>
    <changefreq>weekly</changefreq>
    <priority>0.7</priority>
  </url>
  <!-- ... 残りの自転車も同様 ... -->
</urlset>

robots.txt への追記

robots.txt はGoogleのクローラー（情報収集ロボット）に指示を出すファイルです。ここにsitemapの場所を書いておくと、Googleが自動で読み取ってくれます。

RINCLEの現状: sitemapの場所が書かれていない。下の3行目（焦がし色）を足します。

User-agent: *
Disallow: /version-test/
Sitemap: https://rincle.co.jp/sitemap.xml

Bubble.ioでの設定方法（2026-06-11更新）:
Settings > SEO / metatags の「Customize robots.txt （advanced）」のチェックボックスをONにします。表示された編集欄に上記を入力します。

03

Step 3. Google Search Console — Googleとの窓口

検索結果での見え方を確認・操作する

Google Search Console（サーチコンソール）は、Googleが無料で提供する「あなたのサイトがGoogleにどう見えているか」を確認・操作できる管理画面です。SEOの効果測定は、最終的にすべてこの画面の数字で答え合わせします。

◎Search Consoleが見るもの

検索結果に「出るまで」。何ページ登録されたか・どんな検索語で何回表示されたか・何位か・何回クリックされたか。

GA4が見るもの（Step 4）

サイトに「来た後」。何人来たか・どこから来たか・どのページを見て予約したか。SCとGA4は入口と中身で役割分担している。

仕組み: 検索結果に載るまでの3段階

Googleが行う処理（右端が到達点）
クロール — 用語
Googleのロボット（Googlebot）がページを読みに来ること。ロボットは「知っているURL」しか読みに来ない — だからsitemapでURL一覧を渡す（Step 2）。
インデックス — 用語
読んだページがGoogleのデータベースに登録されること。登録されていないページは、何を検索しても出てこない。

RINCLEは2026年6月の診断でインデックスが2〜3ページしかなかった（=Googleがページを見つけられていない「ディスカバリー問題」）。sitemapとこのStepの作業は、その解決策そのものです。

初回のみ

プロパティの導入

いつやる？ 新しいドメインやサブドメインをSearch Consoleで見たい時。プロパティには2種類あります。それぞれ確認方法が違います。

種類カバー範囲所有権の確認方法
ドメインサブドメイン・http / https を丸ごと（例: rincle.co.jp 全体）DNSのTXTレコードのみ（ドメインのDNS設定を触れる人の作業）
URLプレフィックスそのURL配下だけ（例: https://rincle.co.jp/）HTMLタグ・HTMLファイル・GA4連携など選択肢が多い。Bubbleなら下の手順が簡単

URLプレフィックスをBubbleで確認する手順:

  1. Search Consoleにログイン →「プロパティを追加」→「URLプレフィックス」を選び https://rincle.co.jp/ を入力
  2. 確認方法で「HTMLタグ」を選択。表示されたmetaタグ（<meta name="google-site-verification" ...>）をコピー
  3. Bubble.io Settings → SEO / metatags →「Script / meta tags in header」に貼り付けて保存 → 本番デプロイ
  4. Search Consoleに戻り「確認」をクリック。「所有権を確認しました」が出ればOK
  • 「HTMLファイル」方式を選ぶ場合は、確認用ファイルをsitemapと同じ「Hosting files in the root directory」に置けばよい
  • 既にあるプロパティに人を招く時は、所有者が「設定 →ユーザーと権限 → ユーザーを追加」（プロパティを作り直す必要はない）
誰が何をできるか

権限の仕組み

権限できること
所有者すべての操作+ユーザーやロボットの追加・削除（これだけは所有者限定）
フルデータ閲覧+sitemap送信・URL検査などの操作

  • 月次レポート自動化用のロボット（サービスアカウント）の追加は所有者のみ可能 → 所有者に「制限付きで追加」を依頼する
GOOGLEに知らせる

sitemapの送信

なぜ「送信」するのか: 置いただけだとGoogleが自力で気づくのを待つことになる — 送信すれば「ここに一覧表を置いた」と直接知らせられ、さらに読み込みの結果（何ページ検出・エラーの有無）が画面で見えるようになる。

  1. 左メニュー「サイトマップ」を開く
  2. 「新しいサイトマップの追加」に https://rincle.co.jp/sitemap.xml を入力（ドメインプロパティなので完全なURLで）
  3. 「送信」→ ステータスが「成功しました」になればOK（送信直後は「取得できませんでした」と出ることがある。Googleが再取得して数時間〜1日で直る）
立ち上がりを速くする

URL検査 — 主要ページの「割り込み申請」

なぜやるのか: sitemapは「一覧を渡す」だけで、いつ読みに来るかはGoogle任せ（数日〜数週間）。URL検査から「インデックス登録をリクエスト」するとそのページを優先的に見てもらえる — 行列への割り込み申請のようなもの。1日の上限（10件ほど）があるので価値の高いページから使う。

録画で「なぜ」を見る

Microsoft Clarity（クラリティ）とは

Microsoftが無料で提供する、ユーザーがサイト上でどう動いているかを録画・可視化するツールです。GA4は「何人来たか・どのページを見たか」の数字を教えてくれます。一方クラリティは「どこをクリックしているか・どこで迷っているか」を映像で見せてくれます。

GA4だけの場合

「予約フローで60%が離脱している」→ 分かるけど「なぜ」は分からない

GA4 + クラリティの場合

「60%が離脱」（GA4）→ 録画で「料金が見つからず戻っている」（クラリティ）→ 「料金を明示すれば改善」と判断できる

クラリティの主な機能

セッション録画
ユーザーの画面操作を動画で再生する。「ここで迷ってる」が一目で分かる。
ヒートマップ
ページのどこがよくクリックされているか、どこまでスクロールされているかを色で見せる。
デッドクリック検出
クリックしても何も起きなかった箇所を自動で見つける（＝UIが分かりにくい箇所）。
レイジクリック検出
同じ場所を何度もクリックした箇所を見つける（＝反応が遅い、または動かないと思われた箇所）。

クラリティの導入手順

  1. clarity.microsoft.com を開く。Microsoft / Google / Facebookのいずれかのアカウントでログインする。New project から URL に https://rincle.co.jp を入力する
  2. 表示されるスニペットをコピーする。Bubble.io の Settings > SEO / metatags > Script / meta tags in header に貼り付ける（GA4スニペットの下に追加）
  3. 別のブラウザで rincle.co.jp にアクセスして操作する。数分後にクラリティのダッシュボードに録画が表示されればOK
どちらも無料

Step 5. 効果測定

設定後に何をどう確認するか

設定して終わりではありません。定期的にチェックして改善を続けましょう。

1週間後にチェックすること

  • Search Consoleでインデックス登録されたページ数が増えているか
  • GA4でデータが取れているか（リアルタイムレポートで確認）
  • Search Consoleにエラーが出ていないか
  • OGPが正しく表示されるか（LINEやXにURLを貼って確認）

2〜4週間後にチェックすること

  • Search Console「ページ（カバレッジ）」でインデックス数が増えたか（2〜3ページ → 主要ページ分に増加が期待値）
  • Search Consoleの「検索パフォーマンス」で表示回数・クリック数を確認
  • 狙ったキーワードで検索順位が付き始めているか
  • GA4で自然検索（Organic Search）からの流入が発生しているか
  • ページごとのtitle・descriptionに改善の余地がないか見直す
  • サイトの表示速度をPageSpeed Insightsで確認（LCP 2.5秒以下が理想）

表示速度の現状（2026-06-11 Lighthouse実測）

うまくいかないときは

症状原因の可能性対処法
インデックスが増えないsitemap・内部リンク等のディスカバリー問題（Step 1〜3の設定漏れ）チェックリストを再確認。それでも増えなければプリレンダリング導入を検討（下記）
検索に全く出ないメタ情報が正しく設定されていないGoogle リッチリザルトテストで確認
GA4にデータが来ないスニペットが正しく貼れていないブラウザの開発者ツール > Console でエラーを確認

プリレンダリング（Prerender.io）の導入

Step 1〜3を完遂してもインデックスが伸びない場合の次の一手。クローラーにだけ、JSレンダリング済みの完全なHTML（本文・リンク入り）を返す仕組み。

  • 方式: Cloudflare Workerをドメインのフロントに置き、ボットのリクエストだけPrerenderへルーティングする公式手順がある（人間のアクセスは従来どおりBubbleへ）
  • 所要時間: 30〜45分。Cloudflare無料プランで可。Bubble側のプラン変更は不要（「Bubbleの上位プランが必要」という古いフォーラム情報は過去のもの）
  • 料金: Starter $49 / 月（25,000レンダー）〜、Growth $149 / 月（100,000レンダー）。30日間の無料トライアルあり（2026-06時点）
  • 改善するのはクローラーから見えるHTMLだけ。人間のユーザーの表示速度は1ミリ秒も変わらない。
  • かつての無料プランは2025年10月15日に廃止された。
  • 参考: Prerender.io公式 Bubble統合手順 / 料金改定
