RINCLE 現状課題と改善策

プラットフォームの成長のために解決すべき課題と、施策のロードマップです。

作成: 2026年5月19日 / 最終更新: 2026年8月20日 — 数値は2026年6月11日の旧サイト実測です（検索速度を改善した新サイトは2026年7月上旬に公開済みで、再計測はこれから）。本文の「24店舗」は作成当時の値です（2026年8月20日の実測では店舗56・自転車374台）
01

結論

最も効くのは検索エンジンに見つけてもらう手当て。費用ゼロのPhase 1から

最も効くのは検索エンジンにページを見つけてもらう手当てです。費用ゼロで数日でできるPhase 1（サイトマップ・canonical・ページ別title / meta・Search Console登録）から着手します。2〜4週間の実測を見てから、次の投資を判断したいと考えています。

02

致命的問題: Bubble.ioのSEO問題

2026-06-11 実測で更新（旧サイトでの計測値）
1

インデックスは2〜3ページのみ — 真因は「CSRだから」ではなくディスカバリー問題

2026-06実測: title/meta/OGPはサーバー側で出力済み（旧記述「メタ情報すらない」は誤り）。GooglebotはCSRページもレンダリングできる（Vercel×MERJ調査）。
真因は「sitemap.xmlが404」+「初期HTMLに内部リンク（<a>）が皆無」 → Googleがそもそもページを発見できない。canonical不在で検索パラメータ付きURLがインデックスされる実害も確認済み。

2

初回ロードは想定よりさらに遅い（Lighthouse実測）

旧記述「LCP 3〜5秒」は過小評価だった。Lighthouse実測（モバイル・2026-06-11・旧サイト）: スコア25 / 100、FCP 20.3秒、LCP 49.3秒、総重量9.2MB。
ラボ値のため実回線の体感はこれより短いが、この重量ではどの回線でもLCP 2.5秒合格（Core Web Vitals）はほぼ不可能。モバイルユーザーの53%は3秒以上で離脱する（Google / SOASTA調査）。※検索速度改善込みの新サイトが2026年7月にリリース済みのため要再計測。

3

料金・車種情報がクローラーに見えない（実測で裏付け）

初期HTMLの可視テキストはトップ6文字・店舗詳細31文字のみ。料金・車種・住所はゼロ。本文コンテンツだけがJS依存になっている。

インデックス
検索エンジンの索引
Googleがページを取り込んで検索結果に出せる状態にすること。索引に載っていないページは、どれだけ良くても検索から人が来ません。
サイトマップ
sitemap.xml
「このサイトにはこのページがあります」という一覧をGoogleに渡すファイルです。これが無いと、リンクをたどれないページは見つけてもらえません。
初回表示速度
LCP / FCP
画面の主役が出るまでの時間（LCP）と、最初に何かが出るまでの時間（FCP）です。Googleは合格ラインをLCP 2.5秒としています。
対策

段階を踏んで進める（いきなり作り直しには飛ばない）

  1. Phase 1 — 費用ゼロ・即日〜数日 まずここから
    Bubble標準の設定を完遂します。サイトマップの設置 / canonicalの有効化 / ページ別のtitle・meta / Search Consoleへの登録。真因が「見つけてもらえない」ことである以上、これだけで大きく改善する見込みが十分にあります。インデックス数を2〜4週間実測してから、次の投資を判断します。
  2. Phase 2 — 月額 $49〜
    Prerender.io + Cloudflare Worker で、検索ロボットにだけ組み立て済みのHTMLを配信します（公式の手順があります。作業は30〜45分です）。人が見るときの表示速度は改善しない点にご注意ください。
  3. Phase 3
    Astro等でSEO用のページを別建てにします。店舗×車種のカテゴリページをサブディレクトリで配信します。予約の流れはBubbleのまま誘導します。Bubble.ioを捨てる必要はありません。
  • サイトマップは手動生成方式に決めました（2026年8月20日更新）。Bubble標準の自動生成では、新しいURL構成で店舗・自転車の個別ページが載らないためです。
03

コンバージョンファネル 最重要

ユーザーが「認知」から「リピート」に至るまでの各ステップの課題と改善施策
Step 現状の課題 改善施策

Acquisition （集客）

Step 0
認知
課題 SEO流入ほぼゼロ（2026-06実測: インデックス2〜3ページのみ）、SNSも弱い。そもそもユーザーがRINCLEを知る手段がない。
施策 SEO段階導入（まずPhase 1: Bubbleネイティブ設定・無料 → 効果実測 → SSGランディングページ） / Google Business Profile登録 / SNS運用（Instagram・X）
Step 1
ランディング
課題 SPA読み込みが極端に遅い（旧サイト実測FCP 20.3秒）、その間は白画面 or ローディング。5秒以内にサービスの価値が伝わるか疑問。
施策 ファーストビュー最適化（ヘッドライン+検索バー+信頼指標。星評価はレビューが溜まってから） / スケルトンUIで白画面回避 / ファーストビューだけ静的HTML / CSSで即時表示
ただし: UIが最低限整っていなければ集客しても離脱するだけ。Tier 1（検索バー/料金明示/キャンセルポリシー）は「集客の前提条件」なので集客と並行して実施する。

Engagement （探索・比較）

Step 2
検索・探索
課題 横断検索なし・フィルタなし。初心者はどの自転車を選べばいいか分からない。検索結果0件の体験も未設計。
施策 統合検索バー / フィルタ・ソート / 0件時の代替提案 / 初心者診断モード
日付範囲をまたぐ空き検索のDB設計には落とし穴があります: Bubbleでは「予約済みレコードを除外する方式」が定石で、advancedフィルタ多用はクライアント処理のため件数増で破綻する。検索バー実装前にDB再構築後の新設計（2026年7月に本番リリース済み）と整合を取る。設計レビューを必須とする。
Step 2.5
比較・検討
課題 空き状況の比較ができない。自転車同士の比較もできない。
施策 一覧での空き比較 / 自転車スペック比較 / レコメンド / お気に入り機能
Step 3
詳細確認
課題 料金体系が不明瞭。レビューがゼロ。キャンセルポリシーが見つからない。
施策 料金シミュレーター / レビュー機能 / キャンセルポリシー明示

Conversion （予約・決済）

Step 4
予約・決済
課題 フォーム項目が多い。会員登録が必須。最大の離脱ポイント。
施策 フォームは合計8項目以下に（9項目以上はCVR約4分の1: 4.2% vs 1項目18.2%・Baymard） / ゲスト予約OK（登録強制の撤廃でCVR 20〜30%向上） / カート放棄メール（放棄者の46%は24時間以内に再検索 → 1時間以内+翌朝の2通）

Retention （利用・リピート）

Step 5
予約後〜当日
課題 確認メール1通で放置。当日の流れが不明。不安が残る。
施策 マイページ / リマインドメール / QRチェックイン
Step 6-7
利用中〜利用後
課題 利用中・利用後のフォローが一切ない。リピートにつながらない。
施策 困ったときボタン / ライドサマリー / リピートクーポン / レビュー依頼は返却後24〜48時間以内（投稿レビューの約70%は依頼メール経由） / 購入導線は「試乗履歴つき購入相談予約」として実装

05

PFの生死・収益・保険

店舗の定着・収益モデル・保険の、3つの構造的な課題
店舗の定着

ユーザー側のUIをいくら磨いても、ショップが使い続けてくれなければプラットフォームは死ぬ

先行事例の教訓（2026年6月リサーチ）
Anyca（個人間カーシェア、2024年終了）: 利用会員は直近3年で約2倍に増えたのに、手数料15〜35%と供給側体験の悪化でオーナーが増えず終了。
Spinlister（米P2P自転車レンタル、2018年終了）: 貸し手の手間に報酬が見合わず供給が崩壊（ショップ在庫集約型のListNRideは存続）。
→ 需要が伸びても「ショップの手取り・手間・ROI」が見合わなければフライホイールは止まる。ショップ側体験はUX改善と同格の生存条件。

在庫管理の二重入力問題

ショップが自店の在庫管理とRINCLEの在庫を別々に管理 → 面倒 → 更新されない → 在庫ズレ → オーバーブッキング or 「満車」誤表示。
対策: 管理画面をとにかくシンプルに。Googleカレンダー連携/CSV/API提供。

ショップのROIが見えない

「RINCLEに参加して結局いくら儲かったの？」に答えられないと契約更新時に離脱。
対策: ダッシュボードで月次の予約数/売上/レビュー評価/「レンタル後に購入相談があった件数」を可視化。

写真・データの品質がそろわない

高画質な店舗 vs スマホのぼやけた写真1枚。予約率に直結。
対策: 撮影ガイドライン提供。テンプレート的な商品登録フォーム。優秀ショップを検索上位表示。

サービス品質のばらつき

1店舗の悪い体験がRINCLE全体のブランドを毀損する。
対策: レビュースコアのモニタリング。認定制度（ブロンズ / シルバー / ゴールド）。

収益モデル（2026年6月追加）

収益モデルが未定義 — 「誰からいくら取るか」を決める

レンタル手数料だけでは事業が立たない

体験OTAの送客手数料相場は10〜20%（アソビュー・KLOOK）。掲載無料+成果報酬が業界標準。Anycaの15〜35%は供給離反を招いた危険域。
試算: レンタル単価6,000〜13,200円 × 手数料18% = 1予約あたり1,080〜2,376円。初期の予約数では手数料収益だけで事業は成立しない。

本命収益源は物販送客（try-before-buy）

米Trekは「レンタル料の100%を購入代金に充当」を標準特典化。国内スポーツバイクでは未確立の差別化余地。レンティオ公表値では、レンタル機会の提供で購入数が4倍以上になるケースもある（購入転換率3%の商品でも）。

購入成約への送客フィー（例: 車体価格の3〜5%）なら30万円の完成車で9,000〜15,000円 / 台 — レンタル手数料の数倍。「レンタル料の購入充当」をRINCLE標準特典として全店共通化する。Step 7の「試乗履歴つき購入相談予約」と接続する。

KPIに「テイクレート」「GMV」「レンタル→購入相談率・購入転換率」を追加します。
保険・賠償（2026年6月追加）

保険・賠償の構造的な穴

施設賠償責任保険は「利用者の運転ミス」を補償しない

一般的な施設賠償責任保険の対象は事業者の整備・管理ミス起因のみ。大半の交通事故である利用者の運転ミスは補償されない。自転車事故は数千万円の賠償判例がある。保険加入を条例で義務化する自治体が拡大中。無保険の重大事故1件でプラットフォーム全体の信用が崩壊し得る。

対策: 全パートナー店舗の保険加入状況の棚卸しが最優先

レンタサイクル事業者専用保険（最大1億円補償、6台で年12,000円。自転車安全対策協議会）の加入を加盟基準として義務化を検討。

高額車両（カーボンロード等）の破損時の負担ルールと、免責補償オプション（レンタルバイク業界の定番。収益源も兼ねる）を予約前に明示する — Step 3「本当に大丈夫？」の不安解消に直結。

コールドスタート・計測

レビューゼロの時期をどう抜けるかと、計測の整備
コールドスタートの突破

サービス開始3ヶ月（2026年5月時点）— レビューゼロ・ブランド認知ゼロからどう抜けるか

レビューの種まき戦略

  • パートナーショップの既存顧客にレビュー依頼
  • 体験モニター募集（無料 or 50%OFF）— ただし投稿は任意とする。対価と紐づけない
  • 自転車メディア・ブロガーに体験取材を依頼
  • 目標: 各店舗最低5件、合計120件
ステマ規制（景表法・2023年10月施行）: 「レビュー投稿を条件」に対価を提供すると広告表示義務が発生する。措置命令・課徴金の対象になり得る。投稿してもらう場合は「モニター利用」である旨の表示を徹底。インセンティブは投稿行為のみに付与する。評価内容を条件にしない。

  • ショップのGoogleビジネスプロフィールにRINCLEのリンクを追加
