## 1. 横断の指摘 上位5つ（効果の大きい順）

### ① 「この資料の答え」が最初の画面にない（8枚中6枚）
- competitive-analysis: レポート全体の結論「マルチブランド横断×統一Web予約×リアルタイム在庫はどの陣営も持っていない」が、タブ1の一番下の青い補足alert（5行・半分太字）に置かれている。タブ2以降を開いた読者は一度も見ない。
- differentiation-strategy: たたき台の答え（優先順位①店舗ロックイン②SEO先行③リピート特典④UX）は §05。そこまでに文章主体の章が4つ。
- action-plan: 「今週やることはPhase 1（計測+SEO基盤・無料）」が、12枚のタスクカードを読んでからしか分からない。
- marketing-channels: 結論は §06 に置いてあるが、その前の §01 は統計8枚＋帯＋色違いalert4連で、開いた瞬間に「注記の山」に見える。
- marketing-personas: 「D=既存顧客が最重要」は §01 のキッカー1行のみ。ヒーローのリードは「6つのペルソナを定義する資料です」で止まる。
- current-issues: 「致命的問題」から始まるが、読者に求める判断（Phase 1の無料対策から着手してよいか）が見えない。
- **提案**: 章ナビ直下の最初の部品を「結論1行」に固定する（g3レビュー①と同じ型）。`.alert.alert-green` に `<strong>結論:</strong>` + 1〜2文。競合調査なら「直接競合は全て自社保有型。『多ブランド×統一予約×在庫即時反映』は誰も持っていない＝RINCLEの核」、差別化なら優先順位4つをチップで、アクションプランなら「今週〜2週間はPhase 1（無料）から」。→ **既存部品で可**

### ② タブ番号と章番号がずれる（タブ式3枚すべて）
- competitive-analysis: タブ「3 モデル・料金比較」を押すと章「03・04・05」が並び、タブ4は「06・07」、タブ5は「08」、タブ6は「09・10」。読者は「4を押したのに06」で現在地を失う。
- current-issues: タブ4の中が「04 → 4-2 → 4-3」（4-1がない）、タブ5の中が「05・06」。
- ui-references: タブ2=「03」、タブ3=「04・05」、タブ4=「06」、タブ5=「07・08」。
- 非タブ2枚にも同じ癖: differentiation は「02 → 2-2」（2-1なし）、knowledge-map は最初の2章がアイコン見出し、次から「01〜10」。
- **提案**: 1タブ＝1章、`.section-num`＝タブ番号。タブ内のテーマ分け（表／仕組み図／料金表など）は `.sub-item`（焦がしキッカー＋明朝19px）に落とす。「4-2」「2-2」の枝番も `.sub-item` に置き換える。→ **既存部品で可**

### ③ 保守メモ・内部パス・タスク番号が本文に混ざり、読者に無関係な文字が目立つ位置を占める
- current-issues: 黄色の「2026-08-20注記」（3行）が**5タブ全部**の章01の上に出る。中身は「再計測が必要」という制作側のToDo。
- action-plan / differentiation のヒーロー直下にも同種の黄色注記。action-plan はコード書体で `documents/4_growth/03_seo/sitemap/sitemap-creation-guide.md` を表示。
- 本文中の `task_list #23` `#25` `idea-log.md` `4_growth/03_seo/blog-seo-strategy.md §0` `手法マップ9-3`（channels・personas・competitive タブ6のペルソナ章）。
- ui-references と knowledge-map の footer に「Internal Use Only」— GitHub Pagesで公開しているクライアント向け資料と矛盾する。
- **提案**: 日付は「数字の出典」にだけ残し、更新経緯はヒーローメタの「最終更新 YYYY-MM-DD」1つに集約。旧値の断り（24店舗→56店舗）はヒーローメタに1行「店舗数は2026-05調査時点の公表値」で済ませ、各パネルの注記は削る。mdパス・タスク番号はHTMLコメントに退避し、他資料を指す時は資料名のリンクにする。「Internal Use Only」は削除。→ **既存部品で可**（footer書式の統一は g3②と同じく **規約変更要**）

### ④ 色つき注記（alert・左罫カード・チップ）が積み重なり、色の文法が読めない
- marketing-channels §01: 帯（焦がし枠）→ 緑alert → 紅alert → 藍alert → 黄alert の5連。§03 A1〜A5 は1カードに3〜5枚の色違い注記（ステータス更新／なぜ高ROIか／課題／ペルソナ答え合わせ／お金の出し方）。A5は1画面ぶん太字紅文字。
- action-plan Phase 1: 12カードの下に黄・藍・紅の3枚。current-issues タブ4: 左罫が紅／濃紅／黄のカードが5枚、意味の説明なし。competitive タブ5: 脅威カードの上罫が紅／黄で脅威度を表すが凡例なし。
- 黄（琥珀）のalertはデザインシステムにない（template.css は blue/green/red の3種）。同じ「課題」が黄だったり紅だったりする。
- **提案**: alertは「1話題1枚・2行以内・図表の直下か章末」。色の意味を固定する: 緑=決定／結論、藍=読み方・補足、紅=リスク。「課題」は `ul.notes` の※か `.compare-box.bad` に、「ステータス」は見出し横の `.badge` 1個に。黄を使いたい箇所は藍か※に置き換える。→ **既存部品で可**（黄alertを正式に足すなら **規約変更要**）

### ⑤ 評価スケール（ROI・脅威度・真似されにくさ・相性・実装可能性）の見せ方が5通り以上あり、色が意味を運んでいない
- channels §02: ROIが「最高」=紅塗り／「高」=薄紅／「中〜高」=藍塗り／「中」=藍枠 の4様式。§06 と knowledge-map の地図表: 「5/5」も「1/5」も同じ焦がし色の明朝数字。
- differentiation §03: 「真似されにくさ」列のバッジ文言が行ごとに違う（最も強い／持続的／機能は真似可／構造的優位／いずれ追いつかれる／時間の関数）＝6文言・3色でスケールにならない。
- competitive タブ5: 脅威度が「紅文字」＋「カード上罫の色」＋「!透かし」の三重。ui-references タブ5: ◎ネイティブ／◎プラグインで定番／○可能だが要設計／○可能／◎可能／✕構造的に弱い の6ラベル（「決済」だけ◎に「可能」）。
- **提案**: 3段階は `.badge.brand`（高）／`.badge.ink`（中）／`.badge.plain`（低）に固定し、ラベルも「高／中／低」か「◎／○／△」に統一。細かい理由はセル本文か `td .td-sub` へ。5点満点はセル内の小さな `.hbar`（主役以外は `.fill.dim`）にして長さで読ませる。数字の色は「答え」だけ焦がし。→ **既存部品で可**（セル内ドット式の5点表示を新設するなら新部品）

## 3. 他ページにも広げるべき良い型

1. **ui-references タブ4 §06「RINCLEに落とし込むと、こうなる」** — スマホmock（左）に番号①〜⑦を打ち、右に番号対応の解説を縦に並べる型。1画面で「どこが・なぜ」が対応する。current-issues タブ3の施策mock（T1-1〜T2-4）や決済フロー資料の画面説明にそのまま使える。番号丸は `.pflow-dot` 相当で既存部品化しやすい。
2. **marketing-personas §02・§04「検証状況」の 事実／推測／未検証 バッジ** — 根拠の確度を3語で先頭に付ける文法。competitive-analysis の SWOT・脅威カード、channels の「ステータス更新」、action-plan の KPI ベースライン（要計測）に広げると、日付だらけの注記を減らせる。バッジは `.badge.ink / .plain / .bad` で組める。
3. **current-issues タブ3 の施策mockカードの骨格** — ヘッダー（窓の点＋施策名＋「競合: 全社できていない」バッジ）→ 弱点1行 → mock、の順が全カードで同じ。ui-references タブ2の12社カード（同じ狙いなのに中身の量がばらばら）をこの骨格に揃えると読みやすくなる。
