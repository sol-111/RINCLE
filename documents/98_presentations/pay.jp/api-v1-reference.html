Platform API BETA

マーケットプレイス型・Payouts 型アカウント向け。テナントごとに売上分配・入金・プラットフォーム手数料などを扱う

Platform API の特徴

  • 通常の Charge / Transfer を拡張して利用する部分と、Tenant / TenantTransfer 専用リソースがある
  • Platform 利用時、Plan / Subscription の一部 API は利用不可（公式に「準備中」と記載）という制約あり
  • 認証・JSON 形式は v1 共通項目に準拠。Platform 固有の error[code] が追加される

🏢 Tenant（テナント）Platform

メソッドパス説明
POST/v1/tenantsテナント作成
GET/v1/tenants/:id取得
POST/v1/tenants/:id更新
DELETE/v1/tenants/:id削除
GET/v1/tenants一覧
POST/v1/tenants/:id/application_urls本番申請用 URL 等（承認フロー向け）

💸 Tenant Transfer（テナント入金）Platform

メソッドパス説明

POST/v1/tenant_transfers/:tenant_transfer_id/statement_urls明細 URL 関連
GET/v1/tenant_transfers一覧
GET/v1/tenant_transfers/:tenant_transfer_id/charges紐づく支払い一覧

🔧 Charge / Transfer for Platform Platform

リソース説明
Charge通常の /v1/charges を利用。作成時に tenant 指定が必須、platform_fee 等 Platform 専用プロパティあり
Transferプラットフォーマー側の入金は通常の /v1/transfers。テナント側の入金は /v1/tenant_transfers

Rincle（Bubble）での利用状況

現行本番のBubbleアプリでどう使われているか

API Connector / Webhook 定義

API Connector にはテナント / 顧客 / カード / トークン / 課金 / 返金など api.pay.jp/v1/... の呼び出しがまとまって定義されています。

Webhook では payjp_webhook_charge_captured 等の API Event が pay.jp フォルダにあります。

一覧の正本（コネクタ全件・参照回数・Webhook WF 等）は payjp-rincle-bubble-usage.md（scripts/generate_bubble_docs.py が rincle.bubble から生成）を参照してください。
