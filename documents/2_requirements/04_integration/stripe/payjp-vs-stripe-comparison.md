# 決済基盤の方針 — Pay.jp vs Stripe 比較・移行計画（2026-06版）

> 初版: 2026/5/1 MTG を受けて比較資料として作成、5/8 定例で「Stripe推奨」を提示。
> **本版: 6/12 定例の再調査依頼（タスク#20）を受けて更新し、旧「Stripe移行方針」（4/21合意・stripe-migration-plan.md）を §6 に統合（2026-06-12）。**
> 再調査の前提: 「Pay.jpでオーソリを実装した上で、そのままPay.jpで行くか、Stripeに載せ替えるか」を**短期（工数）と中長期（メリット）の2軸**で評価する。

---

## 0. 結論サマリー

**結論: Stripeに載せ替える。** タイミングは今ではなく、DB再構築完了後に決済全体設計（キャンセルポリシー・振込オペ・月額課金）を固めてから、**集約モデルの実装と同時に**。オーソリの先行実装（80h）はやらない（6/12合意「急がない・二度手間回避」のとおり）。例外は「夏シーズン中の保険」として50円オーソリだけ先に買う場合のみ（経営判断）。

比較した3ルートの定義: **A** = 現行テナント型のままオーソリだけ先行（→結論: やらない）/ **B** = Pay.jpのまま集約モデル化（対抗案・コスト最重視なら）/ **C** = Stripeへ載せ替え+集約モデル化（→**結論: これ**）

以下が判断根拠のメリット・デメリット整理。

### 短期（いま最小工数で決済失敗・キャンセルポリシーに対応するなら）

| | メリット | デメリット |
|--|---------|-----------|
| **ルートA: Pay.jp続行（オーソリ80h）** | 載せ替えなしで最速（見積済み80h・2週間）。決済失敗の事前検知がすぐ手に入る | **80hはほぼ全額が掛け捨て**（50円オーソリ相当のカード有効性チェックは、Stripeでは標準機能=SetupIntentで0円でできるため作り直しになる）。3DS・CVC・紙請求は未解決のまま |
| **ルートC前倒し: Stripeへ今すぐ載せ替え** | 作るものがそのまま最終形になる（捨てる実装ゼロ） | 全体設計が先に必要で「今すぐ」に間に合わない。DB再構築と並走になり非現実的 |

→ 短期だけ見れば**Pay.jp続行が速い**。ただし6/12に「今の件数なら急がない」で合意済みのため、**どちらも着手せずオーソリ先行は見送り**が現実解

### 中長期（集約モデル・月額課金・全体実装後の世界）

| | メリット | デメリット |
|--|---------|-----------|
| **ルートB: Pay.jp（集約化・v1/v2）** | **手数料が安い**（3.3% vs 3.6%。月商1,000万なら月3万円差・ビジネスプラン移行なら月6万円差）。カード再登録不要の可能性（v2は自動マッピング）。3DSも対応済み | **CVC検証が仕様上不可**（決済失敗の温床が残る）。**デポジットを安全に実装できない**（デビット判別不可・v1/v2とも）。Bubbleプラグインなし。v2は未成熟（サブスク未提供・Platform 2027年） |
| **ルートC: Stripe** | 3DS/CVC/領収書が標準・Bubble公式プラグイン・**月額課金（Billing）提供済み**・デポジット制御可・弊社が慣れている | **手数料3.6%で高い**（唯一の構造的デメリット）。カード再登録88人が必要 |

## 1. オーソリ仕様の比較（再調査の核心・2026-06確認）

| 項目 | Pay.jp（API v1・現行） | Pay.jp（API v2） | Stripe |
|------|----------------------|-----------------|--------|
| オーソリ有効期間（**日本発行カード**） | **最大60日**（expiry_days=1〜60、デフォルト7日） | **最大30日** | **最長30日**（日本アカウントの円建て特例・Visa/MC/JCB/Diners/Discover。世界標準は7日） |
| オーソリ有効期間（**海外発行カード**） | 現在は60日まで指定可 → **2026年8月から最大7日**（公式告知） | 現在は30日 → **2026年8月から最大7日**（同告知） | ブランド標準**5〜7日**（Visa非対面5日。日本特例30日の適用範囲は要確認） |
| 部分キャプチャ（オーソリ金額以下） | ○ | ○ | ○（amount_to_capture指定・残額自動解放） |
| オーソリ金額超のキャプチャ | ×（エラー） | × | △（オーバーキャプチャは対象決済のみ） |
| 解放（キャンセル）手数料 | 無料 | 無料 | 無料 |
| 期限前の自動キャプチャ | ×（自前でバッチ管理） | × | ○（automatic_delayed・プレビュー機能） |

**含意:**
- RINCLEのユースケース（予約時50円検証→3日前全額オーソリ→当日キャプチャ / 貸出日のデポジットオーソリ数日間）は**どちらでも実現可能**。「Pay.jpは60日でStripeは7日だから長期予約はPay.jpしか無理」という前回の認識は、日本特例30日の確認により実質解消（30日超の先予約のみ要工夫 = 直前に再オーソリ or 50円検証のみ先行）
- 海外発行カードは2026年8月以降、Pay.jp/Stripeどちらでも実質5〜7日が上限。インバウンド対応を見据えるなら、どちらを選んでも「海外カードはオーソリ期間が短い」前提で設計が必要

### 1.5 補足調査（#25）: 高額デポジットオーソリの与信通過率とリスク（2026-06-12調査）

盗難抑止のデポジットオーソリ（30万円案 / 3〜5万円案）の判断材料。

**通過率**: 「30万円のオーソリが何%通るか」の公開統計は存在しない（通るかどうかは各カードの利用可能枠の残りで決まり、イシュアも開示しない）。代わりに限度額の相場から推計できる:

- 一般カードのショッピング枠は**10〜30万円スタートが相場**（ゴールド50〜100万円）。つまり**30万円のオーソリは一般カード利用者の枠の大半〜全部を要求する**ことになり、日常利用の残高を考えると通らない・通っても他の決済が全部死ぬケースが相当数出る。若年層やサブカードではほぼ通らない
- **3〜5万円案はほとんどのカードで通る見込み**。ただし枠の圧迫は発生する

**デポジット額ごとの必要枠の目安**（推計。仮定: レンタル料の即時決済1〜2.5万円〔実測平均¥10,200・ロード上位/E-Bikeで2〜3万〕が同時に枠に乗る）:

| デポジット額 | 必要な空き枠の目安 | 通る人のイメージ（限度額相場: 一般10〜30万 / ゴールド50〜100万） |
|------------|------------------|------------------------------------------------------------|
| 5万円 | 約6〜8万円 | **一般カードで概ね通る**。限度額10万円のカードだけ利用残高次第 |
| 10万円 | 約11〜13万円 | 限度額10万円は不可。**一般カードでも利用残高次第で脱落が出る** |
| 15万円 | 約16〜18万円 | 限度額20万円でも空き次第。実質「枠に余裕がある人・ゴールド」向け |
| 20万円 | 約21〜23万円 | 限度額30万円でも残高次第でギリギリ。**ほぼゴールド前提** |
| 30万円（参考） | 約31〜33万円 | 一般カードでは構造的に不可能。ゴールドでも利用残高次第 |

> 注意: 判定されるのは「限度額」ではなく「空き枠（限度額−利用残高）」。日常利用がある人は実際の空きはさらに小さい。なお高級車を借りる層はゴールド以上の保有率が相対的に高い可能性はある（楽観材料・未検証）

**⚠ リスク: デビット/プリペイドの即時引き落とし**

- オーソリでも**即時に口座から実額が引き落とされ**、解放後の返金まで数日〜2週間（案内上は最大20日程度）かかる。30万円なら「30万円引かれた！」という重大クレームに直結する
- クレジットカードでも、解放後にイシュア側の枠復活へ数日かかる場合があり、「枠が戻らない」問い合わせ運用は必須

**Pay.jpとStripeの差**（通過率そのものはイシュア次第で差なし。差が出るのは上記リスクを防ぐ制御手段）:

- **Stripeなら「デポジットはクレジットカードのみ」と制御して事故を防げる**（PaymentMethodの `funding` でカード種別を判定・Radarルールでdebit/prepaidブロック可）
- **Pay.jpはv1・v2ともカード情報に種別フィールドがなく安全に実装できない**（v2のOpenAPI定義にもfunding/debit/prepaidの概念が存在しない・2026-06確認）→ デポジット導入の可否自体が決済サービス選定の材料になる

**受容性**: 海外ではホテル・レンタカーの標準慣行。国内も外資系ホテル等では定着しつつあるが、国内レンタサイクルでは稀。増永さんの懸念（6/12: 日本人は慣れていない・店舗が増えるとトラブルが増える・現場は半自動で回したい）はデータと整合する。

出典: [限度額の相場（ライフハッカー）](https://www.lifehacker.jp/article/average_credit_card_limit_how_to_get_limits/) / [デポジットとデビットの注意点（三井住友カード）](https://www.smbc-card.com/nyukai/magazine/tabisapo/knowhow/deposit_trouble.jsp) / [Visaデビットのデポジット返金（PayPay銀行）](https://help.paypay-bank.co.jp/hc/ja/articles/9961580170777) / [StripeでのデビットカードのRadarブロック](https://support.stripe.com/questions/block-mastercard-debit-and-visa-debit-cards-using-radar) / [Pay.jpのデビット/プリペイド対応（ヘルプ）](https://help.pay.jp/ja/articles/3438182)

## 3. 3Dセキュア・CVC（前回から事実関係を更新）

**前提**: 3Dセキュア（3DS）はカード決済時の本人認証（不正利用対策）。**2025年3月末までにEC加盟店への導入が義務化済みで、RINCLEは未導入**（このまま運用を続けること自体がコンプライアンス・チャージバックリスク）。

| | Pay.jpを選んだ場合 | Stripeを選んだ場合 |
|--|---------------------|---------------------|
| 3DS対応の手間 | **自前で組み込み（中規模）**: API Connector+リダイレクト/iframeを自分で組む。機能自体はPay.jpが提供している | **ほぼ自動**: 公式プラグイン+PaymentIntentに標準で組み込まれている |
| カード登録時のCVCチェック | **できない**: 仕様上、誤ったCVCでも登録できてしまう。5/15に確認した決済失敗の温床が**残り続ける** | **できる**: 登録時に検証し、間違いはその場で弾ける |

出典: [PAY.JPにおける3Dセキュア](https://pay.jp/docs/guideline-payjp-three-d-secure) / [3DS組み込み方法の導入指針](https://pay.jp/docs/guideline-select-three-d-secure-type) / [EMV3DS導入義務化（Pay.jpヘルプ）](http://help.pay.jp/ja/articles/9555833-emv3d%E3%82%BB%E3%82%AD%E3%83%A5%E3%82%A2%E5%B0%8E%E5%85%A5%E7%BE%A9%E5%8B%99%E5%8C%96)

## 6. 決定後の移行計画（旧「Stripe移行方針」を統合・2026-06更新）

> 4/21・5/1合意の実行計画。Stripeを選んだ場合のフロー設計と移行ステップ。Pay.jp集約化（ルートB）でも決済フローの構造は同じ（PaymentIntent→PaymentFlow/Chargeに読み替え）。

### 6.1 決済フロー設計

| シーン | フロー | 要点 |
|--------|--------|------|
| 予約時決済 | 予約+カード入力 → PaymentIntent即時決済 → 予約確定・在庫確保 | 全額即時決済（オーソリではない）。現金廃止・カードオンリー。3DSは自動 |
| キャンセル | キャンセル操作 → Refund（全額 or 一部） → 在庫開放 | 即時決済のため**返金**で処理。キャンセルポリシー（#28）が前提 |
| 延長 | 店舗が延長操作 → 登録済みカードで追加PaymentIntent | 元の予約とは別決済。予約IDとの紐付けをDBで管理（延長手数料の取りこぼし#19も解消） |
| 店頭オプション | 店舗が選択 → 登録済みカードで追加決済 | 現在システム外の売上を捕捉できるようになる |
| 高級車デポジット | 通常料金は即時決済 + 貸出日にデポジット分をオーソリ（capture_method=manual・数日間） | 返却時に問題なければ解放・損傷等あればキャプチャ。#25調査済み（3〜5万+クレジット限定が現実解・§1.5）→ 導入可否は経営判断待ち |

### 6.2 店舗への振込・登録

- **振込**: 月次で店舗別売上を集計 → カード手数料+利用料15%を差引 → 振込。紙請求は廃止、未払いリスクゼロ
- **店舗登録**: 決済アカウント作成・審査（現行8ステップ）が丸ごと不要に。店舗情報の代行入力運用は継続
- **領収書**: お金の当事者がユーザー⇔PEDALSTANDARDになるため発行元が変わる見込み。Stripeのレシートメール自動送信を利用（法的要件は要確認）

### 6.3 移行ステップ（2026-06時点のステータス）

| Phase | 内容 | 状態 |
