## 1. 結論

| 観点 | 結論 | ひとこと |
|------|------|---------|
| **どこに書くか** | SEO資産＝**自社サブディレクトリ**（rincle.co.jp/blog/）／拡散＝**note（無料）** | noteの検索評価は後から自社に移せない → 最初から自社に書く |

## 2. どこに書くか — 自社ドメイン vs note

**結論: noteで貯めたSEO評価は後から自社ドメインに移せない**（無料版noteにリダイレクト機能がなく、評価はnote.comに帰属したまま）。「まずnoteで始めて育ったら自社へ引っ越す」は、引っ越しの瞬間に検索評価がゼロリセットされる。

推奨は **「移行」ではなく「最初から分業併用」**:

| 役割 | 置き場所 | 理由 |
|------|---------|------|
| **SEO資産**（地域×コース記事） | **初日から自社サブディレクトリ**（rincle.co.jp/blog/） | 検索評価を自社ドメインに蓄積。後から移せない以上、最初からここに書く |
| **拡散・ブランド用**（運営の想い・店舗ストーリー・イベントレポ） | **note（無料版）** | note.comの集客力・SNS拡散に乗る。検索資産にする必要がないもの |

### noteの実態（なぜ自社が必要か）

- **強み**: ドメイン評価が高く公開直後でも検索流入が得やすい（会員777万人・2024時点）
- **限界**: HTMLタグ・構造化データ・カテゴリ設計のカスタマイズ不可。**検索評価はすべてnote社に帰属**（無料版・プレミアムは独自ドメイン不可）。**noteのリンクは全てnofollow自動付与**＝rincle.co.jpへの評価受け渡しは限定的
- **note proの独自ドメインは月8万円（税抜）**＝予約52件/月分に相当し、現段階では割に合わない
- **併用の定石**: 内容とターゲットを分ければカニバリしない。自社ブログ＝検索KWを狙うSEO資産／note＝初動露出・ストーリー・ファン形成

> 出典: noteヘルプ（独自ドメイン・note pro料金）/ LeadGrid / 東京SEOメーカー / mesut（nofollow検証）/ 301リダイレクト解説 — 詳細URLは各社記事

## 3. どの形式で — LP vs ブログ記事

**結論: SEOで集客するなら「ブログ記事 ＋ 本体サイトのエリアページ」。狭義のLP（縦長1ページ・CV特化）はSEO目的では作らない。**

- 狭義LPがSEOに弱い理由: ①CV特化ページは被リンクがつきにくい ②1ページではKWを網羅できず薄い ③情報収集の検索意図に記事形式が優位
- 使い分け: 「どこを走ろう？」と情報収集中＝ブログ記事／「今すぐ借りたい」＝CVページ
- ※ ただし**作り込んだ複数ページのLPなら話は別**。中身が情報性を持ち複数ページに分かれていれば、それは実質ブログ/オウンドメディアと同じ（呼び名の差）。弱いのは「ペラ1枚の売り込み」

### 「ブログ記事 ＋ 本体エリアページ」とは

2種類のページは**ユーザーの段階が違う**。「本体エリアページ」は新規に作る別物ではなく、**rincle.co.jpの予約サイト側にある既存のエリア検索/店舗一覧ページ**（sitemap化する約500URL）を指す。

| | ① ブログ記事 | ② 本体エリアページ |
|---|---|---|
| 置き場所 | `rincle.co.jp/blog/`（新設・WordPress） | `rincle.co.jp` 予約サイト側（既存・Bubble） |
| 例 | 「神戸の海沿いサイクリングコース完全ガイド」 | 「神戸 ロードバイクレンタル（店舗一覧・予約）」 |
| 見ている人 | 情報収集段階（まだ借りると決めてない） | もう借りる気で探している（取引型） |
| 役割 | **集客**（検索で広く拾う）→ 記事内リンクで②へ | **予約の刈り取り**（ここでCV） |

```
検索「神戸 サイクリングコース」（どこ走ろう）
  → ① ブログ記事「神戸の海沿いコースガイド」      ← 集客（網を広げる）
    → 記事内リンク「このコースを走るなら →」
      → ② 本体エリアページ「神戸 ロードバイクレンタル」 ← 予約（刈り取り）

検索「ロードバイク レンタル 神戸」（もう借りたい）
  → ② 本体エリアページに直接着地 → 予約
```

> 出典: Web幹事 / Nobilista / LANY / 宮城県よろず支援拠点

## 4. 何のツールで — WordPress vs Bubble vs note

### CMSはWordPress

先方（増永さん側）が自分で記事を書く方針のため、**最も馴染みやすい管理画面（WYSIWYG・見たまま編集）と自走しやすさ**を優先（IT知識が浅い・非エンジニアでも書ける／詰まっても日本語の解説・情報量が最多）。

| 項目 | 内容 |
|------|------|
| 月額 | レンタルサーバー **600〜1,100円程度**（エックスサーバー693円〜・ConoHa WING 660円〜） |
| 初期費用 | ほぼゼロ（有料テーマを買う場合のみ1〜2.5万円） |
| 保守 | 更新・バックアップ・セキュリティ対応が継続発生 → **弊社が準委任で対応**（先方の負担なし） |
| 表示速度 | 動的生成のため素のままだと重め → キャッシュ等で実用域に上げる |

※ rincle.co.jpはBubbleホスティングのため、WordPress用サーバーは**別途新規契約（純増コスト）**。Bubble上にWordPressは載せられないので、§6のCloudflare Workerでサブディレクトリに同居させる。

### WordPress vs BubbleのCMS記事（Bubbleで十分か？）

**SEOの強さは WordPress ＞ BubbleのCMS。ただしBubbleでも出せる（インデックスはされる）＝程度問題。** Bubble側でタイトル/descを可変にしても、**「重さ（表示速度）」と「本文がJSでしか出ない」の2つは記事ページでも残る**。

| SEO要素 | WordPress | BubbleのCMS記事 |
|--------|:--:|:--|
| title / description（可変） | ◎ 自動 | ○ 手動だが可能 |
| 表示速度（Core Web Vitals） | ○〜◎ | ✕ **Bubble本体はLCP49秒の実測**・記事も遅い |
| 本文・見出し(h1/h2)の構造 | ◎ | △ JSレンダリングで初期HTMLに乗りにくい |
| JS依存のインデックス | ◎ HTML即提供 | △ 描画はされるが遅延・取りこぼし |
| 構造化データ / canonical / sitemap | ◎ 自動 | △ 弱い・手動 |
| 内部リンク（クロール） | ◎ HTML出力 | △ JS生成でクロールされにくい |
| 立ち上げ工数・コスト | サーバー＋構築 | ◎ 既存Bubble内で完結・追加ほぼゼロ |

→ **本気でSEO上位を取りに行く記事はWordPress。お知らせ・低競合ならBubbleで十分**（次節）。

> 出典: エックスサーバー / ConoHa WING 料金 / seo-setup-guide.md（Bubble実測）

## 5. 用途で振り分け

「全部WordPress」でも「全部Bubble」でもない。**狙いとKWの性質で置き場所を変える**。

| コンテンツ | 置き場所 | 理由 |
|-----------|---------|------|
| 本命のSEO資産（地域×コース記事・主要都市・観光ルート） | **WordPress**（自社サブディレクトリ） | 上位を取りに行く＝速度・構造が要る |
| 店舗の地点 × レンタル（取引型KW） | **Bubble本体の店舗/エリアページをSEO最適化** | §3の通り受け皿は本体ページ。記事を作るまでもない |
| 加盟店の「お知らせレベル」発信（6/19要望） | **BubbleのCMS** | SEOは二の次・手軽さ優先。構築ゼロで店舗が発信できる |
| 運営の想い・ストーリー・拡散 | **note（無料）** | 検索資産にする必要がないもの |

### 「低競合」とは（具体例）

低競合 ＝ 他がほとんど書いていない・すぐ上位に行ける検索語。

- **指名・ブランド系**：「RINCLE ◯◯店」「リンクル レンタル ◯◯」
- **超ローカル×ニッチ**：「△△駅 ロードバイク レンタル」「◯◯川サイクリングロード レンタル 初心者」
- **絞り込みロングテール**：「ロードバイク レンタル 1日 手ぶら ◯◯」

逆に**高競合（＝WordPressで本気を出す主戦場）**：「ロードバイク レンタル 東京 / 大阪 / 名古屋」「しまなみ海道 レンタサイクル」。

### イベント発信は低競合？ → 2種類に分かれる（競合だけでなく"検索需要"も見る）

- **① 自店の小さいイベント告知**（「◯◯店 ナイトライド 6/30」）→ 低競合だが**低需要・時限的**。SEO資産にならない＝**Bubbleのお知らせで十分**
- **② 大型イベント便乗**（「大阪城トライアスロン レンタル」＝6/19で実際に流入）→ **中需要**。イベント名に検索需要があるので拾える＝**記事 or 広告＋LPで取りに行く**

### 地名の粒度で取り方が変わる

細かい地名（店舗のある地点）＝低競合＝Bubbleでも最悪上位は取れる。ただし注意3つ：①競合と一緒に**検索需要も下がる**（取れても流入わずか）②**速度ハンデは常にある**（"勝てるだけ"で理想ではない）③**分散すると内部リンク・クラスタの相乗効果が切れる**（増えるならWordPressに集約）。

| KWの粒度 | 競合 | 取り方 |
|---------|:--:|------|
| 主要都市・観光大型KW（情報型） | 高 | **WordPress記事**（本命） |
| 店舗の地点 × レンタル（取引型） | 低 | **Bubble本体ページをSEO最適化**。記事を作るまでもない |
| 細かい地点 × コース情報（情報型・需要あれば） | 低 | 数が少なければBubble可。増えるならWordPressに集約 |

## 6. 実現方式・始め方

### サブディレクトリの実現（Bubble本体との同居）

- **Cloudflare Workerのリバースプロキシで実現可能**。Bubble本体はそのまま、`rincle.co.jp/blog/*` へのリクエストだけWordPress（別サーバー）にWorkerで振り分ける（Ghost CMS+Bubbleの手順ガイド等、同様の実装例が複数あり）
- サブドメイン（blog.rincle.co.jp）でなく**サブディレクトリ（rincle.co.jp/blog/）を推奨**＝ドメイン評価を1つに集約できる。RINCLEは現状インデックス2〜3ページの弱小ドメインなので、評価を分散させるサブドメインを選ぶ理由がない
- **注意**: BubbleのCloudflare移行により、DNSがA/AAAAレコードだとWorkerがバイパスされる報告あり → **rincle.co.jpのDNS構成の技術検証が必要**（DB再構築後に弊社で実施）

### 始め方と順序

1. **前提**: DB再構築完了 → SEO基盤一式（メタ情報・sitemap・Search Console・GA4）→ Cloudflareフロント → サブディレクトリにWordPress構築。基盤構築は**準委任で対応**
2. **記事の書き溜めは今日から可能**（原稿化しておきCMS完成後に一括投入）。noteは技術的前提がないので即日開始できる
3. **優先KW**: 最優先「観光ルート名×レンタサイクル」（しまなみ海道・ビワイチ等）、次点「都市名×ロードバイク レンタル」。「スポーツバイク」軸の文言は使わない
4. 1本目は加盟店が実在し実走できる地域（例: 神戸）から。記事テンプレ1種（コース概要・マップ・立ち寄りスポット・レンタル導線）を設計して量産

> noteは無料版で開設し拡散・ブランド用に限定。記事末尾からrincle.co.jpへ誘導（nofollowだが人間のトラフィックは流れる）。同じ記事を両方に置かない（重複コンテンツ回避）。
