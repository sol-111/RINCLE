# E2E改修計画（リリース前タスク#14）— 設計: Fable / 実装: Opus・Sonnet / レビュー: Fable

## 目的

`rincle.e2e.ts`（17テスト・旧ブランチ version-5398j 向け）を、新構築ブランチ **version-13fge** で全て通るように改修する。テストの検証意図は変えない。

## 確定事項（設計判断）

- **BASE_URL**: `https://rincle.co.jp/version-13fge`（ユーザー指定）
- 旧ブランチ version-5398j は404（確認済み）
- テストの意図・検証項目は維持。**通すためにexpectを弱めることは禁止**（例: URL検証を緩くする等）。どうしても通らない場合はfailのまま原因を報告する
- 新アプリに存在しない機能は `test.skip` + 理由コメント（テスト削除禁止）

## 新アプリの構造（エクスポート解析済みの事実 — プローブの当たりを付けるのに使う）

### ページ構成（旧→新）
| 旧 | 新 |
|---|---|
| index（SPA・全部入り） | index（top）+ 専用ページに分割 |
| /index/mypage | **/mypage**（専用ページ化。userinfo・user_reservation部品で構成） |
| ログインポップアップ | **/signin** ページ（`?mode=sign_in\|sign_up\|pass_reset\|conformation\|add_userinfo`、`&role=user`） |
| /index/cart | **/reservation** ページ（cart部品が載る。予約確定メールの送信元） |
| /user_reservation_list | /user_reservation_list（同名継続） |
| 自転車詳細（index内） | **/bicycle_detail**（`?bicycle=<id>&start=&end=&reserve=&change=` をWFで読む） |
| 店舗詳細 /shop_detail/<id> | /shop_detail（`?shop=<id>&start=&end=&type=&free=&e-bike=`） |
| 検索（index内） | **/search** ページあり（index上の検索UIも残っている可能性 — 要プローブ） |
| /index/guide 等の静的コンテンツ | option set `page` に guide/howtopay/privacypolicy/contact/user_edit/news_detail/topics_detail 等29値が残存 → `/index/<param>` ルーティングが生きている可能性が高い（要プローブ）。faqの有無は不明 |
| 利用規約等 | **/legal** ページ新設（統合先の可能性） |

### Bubble特有の既知テクニック（旧テストから継承・そのまま使える想定）
- `selectPikadayDate()`: `aria-owns`でカレンダー特定→月送り→日クリック→Close
- `clickBubbleButton()`: `get_precomputed`差し替えで`button_disabled`回避→jQueryハンドラ直接発火
- picker/selectのインデックスは新DOMで変わる可能性大 — プローブで再確定すること

### 予約フローのDB挙動（突合表・予約データ遷移シートより）
カート追加時に reservation（status=仮情報）が作られ、申込確定で status=来客待ち になる。テスト9のキャンセルで api:cancel_reservation が走り status=キャンセル+在庫戻し。**テストで作った予約は必ずキャンセルまで到達させる**こと。

## 制約（実装エージェントは厳守）

1. **アクセス先は `https://rincle.co.jp/version-13fge` のみ**。本番（version-liveや素のrincle.co.jp配下ページ）への操作禁止（GETで開くのも避ける）
2. **実カード決済をしない**。支払い方法の選択肢があれば「店頭決済」を選ぶ。カード番号入力が必須の画面に到達したら、そこで止めてスキップ/レポート（カード情報入力・送信は禁止）
3. **.envは読み取り専用**（編集禁止）。パスワード等の秘密値を標準出力・ログ・コード内に書かない（process.env参照のみ）
4. playwright.config.ts は変更しない（headless:true・workers:1・serial維持）
5. 予約日時は .env の値をそのまま使う（RINCLE_DATE=2026/07/12 09:00 は開始時刻が過去の可能性あり。バリデーションで弾かれたらその事実を報告。勝手に日時を変えない）
6. 調査は `inspect_*.js` パターン（新規プローブは /tmp か probe_*.js 命名で作る）。`documents/rincle.bubble`（9.6MB JSON）はpython3で検索してワークフロー/要素の実体確認に使ってよい
