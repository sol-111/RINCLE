# 2環境比較E2E結果（2026-07-16実施）— version-test vs version-43erq

背景: 「作業ブランチ（version-43erq）の内容がテストブランチ（version-test）にうまくマージできていなさそう」の検証依頼。
方法: 既存4スイート全43本を両環境で通し実行（DB共有前提のため順次実行）＋ 主要22ページの可視テキスト・スクリーンショット突合（未ログイン/ユーザー/店舗/管理者の4視点）。
実行条件: RINCLE_DATE="2026/07/18 11:00"〜19:00（土曜・予約可能ウィンドウ内）。テストは `RINCLE_BASE_URL` で接続先を切替（今回スイートに追加した環境変数。未指定時は従来どおり43erq）。

## 結論

**マージ漏れの証拠は見つからなかった。** 挙動（処理）は2環境で完全一致し、UI差分はむしろ「43erq側だけにある管理画面の2重描画」の1点のみ。
一方で、**7/14に全緑だったスイートが現在は両環境共通で10件failしており**、7/14以降の変更が（マージを介して両環境に等しく反映された上で）ユーザー検索・管理画面の一覧系・予約決済ステップを壊している状態。「テストブランチだけおかしい」のではなく「両方とも今おかしい」が実態。

## 1. 処理差分: なし（43本すべて同一結果・同一エラー）

- 両環境とも **28 pass / 1 skip / 14 fail相当**（直列実行の停止をgrepで分割して全43本を消化）
- fail 10種の失敗箇所・エラーメッセージ・アサーション位置まで両環境で一致（正規化ログのdiffはフレーク2行のみ）
- ログ: scratchpad `run_43erq.log` / `run_test.log` / `run2_*` / `run3_*`（セッション一時領域）

## 2. UI差分: 1点のみ — 43erqの店舗管理・管理者画面が2重描画

- **店舗管理6ページ・管理者6ページすべてで、43erq側はページシェル（サイドナビ+見出し+本文）が縦に2回重複描画される**。version-testは1回で正常。再ロードでも再現（新規登録ボタン・ナビ項目が常に×2）
- 可視テキストの行セット比較では、重複を除くと**全ページ完全一致**（コンテンツ・ナビ項目・文言の差なし）
- ユーザー側ページ（トップ/検索/自転車詳細/マイページ/予約一覧/ガイド/契約系/サインイン）は**1文字単位で一致**
- → 43erq側で編集中のレイアウト複製か、43erqのみのバグ。**version-test側が「欠けている」のではない**（方向が逆）

## 3. 【要注意】両環境共通のfail 10件 = 7/14以降の変更による劣化（マージ起因ではない）

7/14時点は42本全緑（skip1）だった。現在の共通failは以下。Stripe載せ替え（#35）等の作業中変更またはデータ変化が原因の可能性が高く、山本さんへの確認推奨。

| # | テスト | 症状 |
|---|---|---|
| 1 | 予約フロー | 支払いステップに**「店頭決済」の選択肢が存在しない**（Stripe実装中の影響が濃厚。テストは安全のため店頭決済必須） |
| 2 | 店舗・自転車一覧 | 一覧の行が**非表示**（ヘッダ「種別」がDOMに在るがhidden。スクショでも本文空） |
| 3 | 管理者・加盟店一覧 | リストが**1件も描画されない**（SEINO以前に全店舗が空） |
| 4 | ユーザー検索（栃木） | **「表示できる店舗がありません」**＝テスト店舗が検索に出ない → タイプフィルタ精度テストも連鎖fail |
| 5 | 非表示切替 | ステータスselectの選択値が「ユーザー表示/非表示」という結合文字列（未選択/placeholder状態の疑い。#4の原因候補） |
| 6 | オプション作成 | フォームから**「全ての自転車に適用する」が消えた**（UI変更） |
| 7 | 休業日のユーザー反映 | 店舗側カレンダーの休業日9日に対し**ユーザー側カレンダーは0日**（反映が切れている） |
| 8 | 店舗予約一覧（回帰④） | 予約カードが1件もパースできない（表示形式変更の可能性） |

補足:
- #2〜#5は「一覧系の描画/データ」の共通劣化パターン。自転車詳細への直接アクセス（bicycle_detail?bicycle=ID）は両環境とも正常表示
- 直接原因がアプリ変更かデータ変化（共有DB）かは本検証では切り分け不能（Bubbleエディタ側の確認が必要）
