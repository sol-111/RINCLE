追加 — 手順書の分節に
小見出し分節
章の中に複数のテーマが並ぶ時、h4の平坦な連なりは境界が見えず読みにくい。焦がしキッカー（役割や番号の一言）+明朝19px見出しの2段で分ける — 章見出しと同じ文法のミニ版。キッカーは省略可。白面カードで囲うのは不可（用語解説と紛れ、箱が並んでうるさくなる・2026-08-26）。
STEP 3-3 — GOOGLEに知らせる

sitemapの送信

なぜ: 置いただけだとGoogleが気づくのを待つことになる。送信すれば直接知らせられ、読み込み結果も画面で見える。

  1. 左メニュー「サイトマップ」を開く
  2. URLを入力して「送信」
追加 — 平易な日本語の要
用語解説
専門用語は本文の脇でその場で開く。明朝の用語名+短い説明。
Data API — 用語
画面を開かなくても、プログラムからデータベースの中身を一覧でもらえる窓口。これを使うと店舗・自転車の全IDが数回の通信で取れる。
追加 — 意思決定の見せ場
×○対比
ダメな案と採用案を必ず並べて、理由まで書く。
×Bubbleの自動生成

新サイトはURLの後ろにIDを付ける方式のため、店舗・自転車の1件1件のURLが載らない。

○手動で組み立てる（採用）

ID一覧を自分たちで集めてsitemap.xmlを組み立てる。材料はページ一覧とID一覧の2つ。

追加 — 手順の定番
番号つき手順
番号の丸を罫線でつなぐ。1行1操作。
  1. Bubbleエディタ → Settings > API タブを開く
  2. データ種類の一覧で shop と Bicycle の2つだけにチェック
  3. 本番に反映（デプロイ）する
追加 — 細かな注意書き
注意リスト
※印の箇条書き。アラートにするほどではない注記に。
  • ファイルはバージョンごとの扱い。本番で見えない場合はアップ先を確認
  • ファイル名はアプリのページ名と重複してはいけない
追加 — ページの締め
まとめ帯
ページ内で唯一の濃い塗り。墨の帯+明朝+チップの流れ。

運用のまとめ — 店舗・自転車が増えたら

手順3 再生成 → 手順4 再アップロード → Googleが自動で再読込

頻度（月1回など）は増永さんと相談して決める。

追加 — 技術資料用
コードブロック / URL構造図
