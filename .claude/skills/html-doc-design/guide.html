DESIGN SYSTEM — 説明書
GUIDE

html-doc-design 使い方ガイド

クライアント向けHTML資料を作るClaude Codeスキルの説明書です。主の様式は「読めるデッキ」で、手順書と定型レポートだけ「誌面」で組みます。中身の分担・使い方・社内への配り方をまとめました。

01

そもそもスキルとは

サーバー登録も設定画面もない
スキル — 用語
Claude Codeに「この種の仕事はこう進めて」と教える指示書ファイルの束。フォルダを置くだけで登録される。

動く仕組みは3段階。普段は説明文1行分しか場所を取らず、必要な時だけ全部が読み込まれる省エネ構造になっている。

  1. SKILL.mdの説明文（description）だけは常に見えている — どの案件でClaudeを開いても、名刺のように1行だけ提示されている
  2. 該当する依頼が来ると本文が読み込まれる — 「HTML資料を作って」「デザインを統一して」でClaudeが自分でスキルを開く
  3. 残りのファイルは必要な時だけ — 本文に「template.cssとsnippets.htmlを読め」と書いてあるので、作業に入った時だけ読まれる
確実に発動させたい時: チャットで /html-doc-design と打ってから頼む。
02

考え方

器は資料の種類で決め、部品は伝えたいことの形で選ぶ

コンサルの成果物の型で、1枚ごとに主張が完結する資料を組みます。部品は「伝えたいことの形」で1つに絞って選びます。

様式位置づけ使う資料
読めるデッキ既定提案・報告・分析・比較検討・方針・見積。事前に送って読んでもらい、打合せでも映す資料
誌面付録手順書・定型の月次レポート・用語集・APIリファレンス。上から順に読む資料
画面UI付録資料の中でアプリの画面を再現するときだけ
  1. 器を決める：上の表で様式を選ぶ。迷ったら読めるデッキ
  2. 伝えたいことの形で章を引く：gallery.html は 文法・器・答え・数字・比べる・流れと時間・論理・補足と根拠 の順に並んでいる
  3. 章の中で1つに絞る：似た部品が2つ残ったら SKILL.md の選択表で決める。同じ部品がデッキにも誌面にも置ける
  • 部品の多くは、経産省の委託調査報告書29本（BCG・NRI・みずほR&T・トーマツ・デロイト・ADLほか）から取り込んだ型です。特定の会社に寄らず、1枚で答え・根拠・前提に当たれるか、誤読しないか、作り手が再現できるかで選んでいます（経緯は decisions.md）。
03

中身のファイルと役割

何を守るか・どう見えるか・どう書くか
~/.claude/skills/html-doc-design/
├── SKILL.md       # ルールブック（様式の使い分け+原則+読めるデッキ+部品の地図+誌面のページ構造）
├── decisions.md   # 規約を決めた経緯・教訓（普段は読まない。変えたくなった時に）
├── template.css   # 核部品のCSS（コピーして使う。色はアイビスに固定）
├── parts.css      # 画面UIの部品のCSS（ボタン・モーダル・かんばん等。画面を再現する時だけ）
├── snippets.html  # 各部品のHTML雛形集（gallery.html と同じ章の順・コピーして使う）
├── gallery.html   # 資料部品の見本（見た目の正本。8つの章＋付録A 誌面）
├── gallery-ui.html # 画面UIの部品の見本
├── deck.html      # 読めるデッキの器（一覧表示が既定・Pキーで送り・PDF化）
├── shell.html     # 複数ページをまとめるSPAシェルの雛形（サイドバー+iframe）
├── lint.py        # 規約の検査プログラム（書いたら必ずかける。使い方は「4 使い方」）
├── guide.html     # このページ（人間用の説明書）
├── README.md      # 人間用の説明書（テキスト版）
└── review/        # レビューの道具（内容レビュー content-prompt.md・初見レビューの shoot.mjs / prompt.md / README.md）
ファイル役割ひとこと
SKILL.md何を守るかBCGの作法（ゴシック・緑の見出し・黒を使わない）・数字には出典・部品の優先度 などのルール
template.css / parts.cssどう見えるか色の変数（トークン）は先頭の:rootに集約。色はアイビスに固定
snippets.htmlどう書くか部品ごとのコピペ用HTML+演出スクリプト
gallery.htmlどう見えるはずか見た目の正本。部品を追加したらここにも見本を足す（5点セット更新の掟）。画面UIは gallery-ui.html
deck.htmlどう組むか読めるデッキの器。コピーして1枚ずつ足す
lint.py守れているか規約の検査プログラム。書いたら必ずかける（詳しくは「4 使い方」）
shell.htmlどうまとめるか資料が複数ある案件の入口ページの雛形
decisions.mdなぜそうなったか規約の経緯と教訓。ルールを変えたくなった時に読む
見た目の正本は gallery.html。部品や規約を追加・変更したら template.css（実体）・snippets.html（雛形）・gallery.html（見本）・SKILL.md（ルール）・lint.py（機械チェックできる規約のみ）の5点セットで更新する — CSSだけ直すのが典型的な漏れ方。
04

使い方

頼み方・検査・色・更新の流れ

ふだんの頼み方

  • 「この調査結果を、いつものデザインでHTML資料にして」（提案・報告は読めるデッキ、手順書・定型レポートは誌面で組まれる）
  • 「このページをデザインシステムに合わせて刷新して」

書いたら必ず検査 — lint.py

lint（リント）検査プログラムの通称
書き上がったHTMLがこの様式の規約を守れているかを、機械的に洗い出す検査プログラム。人が目で見ても気づきにくい違反 — 文体の揺れ・部品の組み間違い・旧様式の残骸 — を数秒で全部挙げる。Claudeがページを書いたら必ず実行する決まり。人が手で動かして確かめることもできる。
# ファイル1つでも、フォルダごと（中のHTML全部）でもかけられる
python3 ~/.claude/skills/html-doc-design/lint.py 検査したいHTMLかフォルダ

# 結果の見え方 — 指摘ゼロなら OK、1件でもあれば NG と指摘の一覧が出る
OK   seo-report-2026-08.html
NG   proposal.html
     - 接続助詞「し、」で文をつないでいる(句点で切るか読点を落とす): …
     - 項目名の字下げに全角空白の直書き(td.label.indを使う): …
検査の種類例
構造タグの開閉・タブとパネルの対応が取れているか
統一性ヒーローの部品・キッカー文言・ロゴの有無が全ページで同じか
部品の組み方デッキは1枚1メッセージ・表10行まで・本文14px相当以上・付録は40枚に数えない・誌面は結論を01章に置く・答えの行と推奨列の面を同じ表に置かない・図は主張を書いたfigureで包む・章番号は01始まり・h2は1行・小見出しの番号はハイフン式・statは「ラベルが上」・アラートは緑/藍/紅の3色・色ベタの行ハイライトを作らない・ページ固有CSSで共通部品を作り直さない など
文章・敬語半角括弧・全角スラッシュ・「〜し、」等の文つなぎ・二重敬語「ご〜される」
残骸旧様式の色の直書き・絵文字（アイコンはSVGを使う決まり）
一覧の正本検査項目の全一覧は lint.py 冒頭の説明文が正です（ここは要約）
  • 部品カタログ（gallery.html のような見本集）は、冒頭に <!-- lint-mode: specimen --> と書くと文脈依存の検査（章ナビの位置）だけ免除されます。
  • 固有名詞の絵文字は --allow-emoji "固有名詞の絵文字" で許可できます。資料集でページごとにキッカーが異なる構成は --multi-doc。
  • 検査で拾えないもの — 図解の役割色と凡例・緑の重ねすぎ・リンク先の実在 — は目視で確認します。

色について — アイビスの緑に固定

2026年9月29日から色はアイビスに固定しました。主色はロゴの葉の #72B000（面・印・棒）、見出しと強調の文字は #4E8A00、当社の独自提案だけオレンジ #F87830。案件ごとのブランド色への差し替えはしません。

デザインを変えたくなった時 — 更新の流れ

  • 更新は template.css（実体）→ snippets.html（雛形）→ gallery.html（見本）→ SKILL.md（ルール）→ lint.py（機械チェックできる規約のみ）の5点セット。リポジトリ（gitで共有するプロジェクトのフォルダ）に同梱している案件では、更新後にリポジトリ側へコピーする

社内展開

配る=フォルダをコピーする
置き場所使える範囲向いている使い方
~/.claude/skills/その人の全案件個人の標準装備にする
リポジトリ/.claude/skills/そのリポジトリを開いた人全員チーム展開はこちら。gitで共有され、pullした人に自動で配られる
 
# チーム展開の手順（例: RINCLEリポジトリ）
mkdir -p .claude/skills
cp -r ~/.claude/skills/html-doc-design .claude/skills/
git add .claude/skills
git commit -m "docs: HTML資料デザインシステムをスキルとして同梱"
個人版とリポジトリ版が両方ある場合、そのリポジトリ内ではリポジトリ版が優先される。
