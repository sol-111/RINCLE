# 設計判断の記録（decisions）

SKILL.mdの規約が「なぜそうなったか」の経緯と教訓。**普段の資料作りでは読まなくてよい**。規約を変えたくなった時・判断に迷った時に、同じ議論を繰り返さないために読む。新しい判断を下したらここに追記する（新しい日付を上に）。

## 2026-09-29 — 幅のメディアクエリを `screen and` に限定する（印刷の崩れ）

- **症状**: デッキをChromeでPDFにすると、3列のはずの統計カード列`.stat-row`が1列に縦積みになり、数字が巨大化してスライドから溢れた。画面では正しく3列。
- **原因**: Chromeの印刷レイアウトの幅は用紙幅（既定のLetterから余白を引いた約739px）で評価される。`@page{size:338.67mm 190.5mm}`を書いても、幅のメディアクエリはこの値で判定される。そのため**画面の狭幅用フォールバック（max-width:760px / 900px / 1100px）が印刷でも全部発火していた**。
- **対処**: 幅のメディアクエリを全部 `@media screen and (...)` に限定した（760px×2・900px・1100px・min-width:761px）。印刷の見た目は`@media print`のブロックだけが決める。
- **教訓**: 印刷を持つ様式では、幅のメディアクエリに必ず `screen and` を付ける。付け忘れは画面では絶対に見つからない（PDFを実際に1枚ずつ画像にして見るまで気づかない）。
