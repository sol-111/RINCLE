# HTML資料デザインシステム — 誌面エディトリアル

RINCLE案件で確立したクライアント向けHTML資料のフォーマット（2026-08-21に「誌面エディトリアル」様式へ全面改定）。雑誌の誌面のように、**罫線と余白で組み、明朝の見出しで読ませる**。どの案件でもこの構成・部品で組み、**ブランドカラーだけ案件ごとに差し替える**。見た目の正本は同フォルダの **gallery.html**（全部品の見本）。部品のHTML雛形は **snippets.html**、CSSの実体は **template.css**（核）+ **parts.css**（拡張）。

## 原則

1. **自己完結**: CSSは`<style>`にインライン（または同一リポジトリ内の共有CSS）。外部CSS/JS/CDN・画像CDNは使わない。**唯一の例外はGoogle Fonts** — 見出し=Shippori Mincho（明朝）・本文=Noto Sans JPを`<link>`で読み込む（snippets.html冒頭）。フォールバックにシステムフォントを並べ、オフラインでも読めるようにする。和文は`palt`、表は`tabular-nums`
2. **ブランドカラーは「焦がしトーン」に落として差し色に**: 案件のロゴ/ファビコンから実測した原色をそのまま使わず、彩度を落とし暗めに寄せた editorial トーンを `--accent` にする（RINCLE: 原色#F95320 → 焦がし#B8532F）。中間色（--paper/--ink/--line）はブランドの色温度に寄せる。役割色も彩度低め: 承認の緑#3E6B4F・警告の紅#A8323E・補足の藍#3B5B84・お金の琥珀#C99A2E
3. **罫線と余白で組む・影と塗りは使わない**: 面の区切りは1pxの罫線（強#DCD3C8/弱#E5DDD2）と余白。カードは白面+罫線のみ。**影は浮かぶ部品（メニュー・モーダル・トースト・スライドの額）だけ**。濃い塗りは「まとめ帯（墨）」と「コード面」だけ。**セクション内の部品はコンテナ幅いっぱいに使う** — 用語解説・手順・対比・図解などに個別のmax-widthを付けて右側を空けない（右端が揃わずガタガタに見える）。**ヒーローのリード文も絞らない**（旧版はリード文だけ680pxに絞る例外を置いていたが、中途半端な位置で改行されるため2026-08-25に廃止）
4. **見出しは明朝・数字も明朝の英数字**: 見出し・項目名・数字の見せ場はShippori Mincho。数字は英数字（漢数字は使わない）。セクション番号は薄い大きな明朝数字（rgba墨8%）を見出しの左に敷く。**見出しの階段は4段で固定**: H1=52px（ページ題）/ H2=30px+薄い大数字+キッカー（章）/ 19px=中見出し（素=h3・テーマの区切りにはキッカーを着せる=.sub-item の2形態のみ）/ h4=16px（小見出し）。**これ以上パターンを増やさない** — 変種は意味があるとき（キッカー=テーマの予告）だけ
5. **正本の明記**: mdが正本の場合、footerに「正本: <mdパス>（md更新時はこのHTMLも同期すること）」
6. **平易な日本語**: カタカナ専門用語は日常語に開く。専門用語は`.term`部品でその場で解説
7. **数字には出典**: 実測値は日付つきで書く。ヒーローに統計チップは置かない
8. **アイコンはSVGスプライト**: 絵文字・文字記号は使わず、snippets.htmlの12種スプライトを`<use>`で参照（線幅1.5）
9. **演出は3点セット**: 読み進みバー・セクションのふわっと表示・章ナビ現在地ハイライト（snippets.htmlのスクリプト。JS無効/アニメ抑制設定でも壊れない）
10. **チャート**: 出典のある数字のみ・1ページ1〜2個。ドーナツは線2.4の細リング・**中央は大きな数字だけ**（単位・出典は凡例側）。データ色は 焦がしブランド→墨→下地 の3段まで。**前月比較などの2値比較は横棒ペア**（`.bars`: 当月=焦がし/前月=下地・値は明朝で棒の右）。KPIの見せ場は`.stat-row`（**ラベル→明朝特大→前月比`.d.up/.down`の順** — ラベルを数字の上に置いて見出しとして効かせる）
11. **図解の役割色は固定**: ユーザー=藍/店舗(相手方)=緑/システム=焦がしブランド/お金=琥珀/例外=紅。凡例を図の直下に必ず置く。スイムレーンは横=時系列フェーズ・縦=役割レーン、**例外の列はピンク面+破線**、**お金の行は琥珀**。**フロー図の使い分け（2026-08-25決定）**: 複数の役割がやり取りする流れ（決済・承認・キャンセル等）=**レーン型`.lanes`**（縦=役割・横=時系列の格子。役割間のタイミングが格子で揃う。「お金の動き」行を琥珀で入れると金流が一行で伝わる）／ほぼ単役割の直線フロー（認証・検索等）=**箱矢印`.swim`**（レーン型だと1行だけの表になって間延びするため）。役割間の位置合わせに固定px幅の空白divを使うのは禁止（崩れの元 — レーン型に置き換える）。図の下で手順を詳しく語る時は**役割つき縦フロー`.pflow`**（番号丸=役割色の輪郭+明朝数字・役割キッカー・左罫の注記）。状態遷移図は`.swim`の応用で組む（状態=チップ・到達点=hot・離脱=例外の枝）。段階ごとの絞り込みは**ファネル`.funnel`**（棒の幅=構成比・段間に転換率）。`.swim`型の規格: ノード=**ニュートラルなピル型チップ**（白面+1px罫・角丸999px。役割は行ラベルが示すのでノードに色は付けない — 部分的な色バーは2026-08-25に廃止）・判定=墨罫+太字・強調=焦がし輪郭+薄い面・エラー=紅の破線・矢印は文字でなく線+矢じりを描く（`.swim-arrow`）・分岐は左レール+色つきキッカーラベル

## ページ構造

1. **hero（全ページ同一・全幅）** — 紙の背景に、上枠（ロゴ+キッカー｜資料番号・墨の下罫線）→ 明朝の大見出し → リード → メタ行。角丸カード型ヒーローは禁止
2. **章ナビ（必須）** — ヒーロー直下に-64pxで重ねる罫線グリッドの索引（明朝番号+章名+一言）。「何もなし」禁止。通常ページ=`.flow`（アンカー）、タブページ=`.flow-tabs`（同じ見た目でパネル切替）。ピル型タブ禁止。最大8個（4列×2行）。項目数が4の倍数でなくても罫線は途切れない（template.cssの::after+:has()が空きマスを自動で埋める仕組み。消さないこと）。サマリーカードをヒーローに重ねない・章ナビや結論と重複する要点カード列を置かない
3. **section** — 薄い大番号（.section-num）+明朝h2+キッカーのサブ見出し。**章の背景は白⇄紙の交互**（最初の章=白・画面幅いっぱいに染み出す）で章変わりを見せる — 縦資料は余白だけだと章の切り替えが分かりにくいため（2026-08-21決定）
4. **部品** — card / term / **小見出し分節.sub-item**（章の中のテーマを「焦がしキッカー.kick+明朝19px見出し」の2段で分ける — 章見出しと同じ文法のミニ版。キッカーは省略可。h4の平坦な連なりは読みにくいが、**白面カードで囲うのも不可** — 用語解説と紛れ、箱が並んでうるさくなる） / alert(藍緑紅) / compare / table（上罫墨2px・項目名明朝・数値列は td.num/th.num で値も見出しも右揃え。**当月/前月/増減の比較表は`.table-mom`**: グループ見出し行`.tgroup`で束ね、当月=墨・前月=グレー・増減=緑/紅の意味色（**増えたら悪い指標〈キャンセル等〉は色を反転**）・行間は詰める — 長いフラット表は読めない） / codeblock / ol.steps / ul.notes / badge / chart(.stat-row/.bars/ドーナツ/ファネル) / 図解（レーン格子.lanes/横フロー.swim/役割つき縦フロー.pflow/フェーズ帯.phases） / recap
5. **recap（任意）** — 末尾のまとめ帯（墨。ページ内で唯一の濃い塗り。チップフロー入り）
6. **footer** — 罫線+正本パス

CSSは `template.css` をそのままコピー（トークンだけ案件ブランドに差し替え）。部品のHTML雛形は `snippets.html`。

## スライド（16:9・定例でそのまま映す）

`.slide` の型7種: 表紙 / 章とびら（薄い大番号） / 1メッセージ / ビッグナンバー / 2分割（主張+根拠） / ×○比較 / 締め（やること・担当・期日の3列表）。共通規格: 下枠は左=ブランド名・右=ページ番号（表紙のみ日付）、1枚に言いたいことは1つ、表は5行まで、本文の最小は投影で読める18px相当。

## 長いページはタブ化

縦に長いページ（画面5〜6枚分超）は章ナビ型タブで章を切り替える: `.flow-tabs`+`.tab-btn`(fnum/ft/fd)+`.tab-panel`+切替script（snippets.html）。ハッシュ更新で直リンク可。ページ内アンカーが多いページはタブ化しない。

## 複数ページをまとめるSPAシェル

資料が複数ある案件は index.html（サイドバー+iframe方式）でまとめる: `pages`配列に1行足すだけの構造。サイドバーはダーク地+ブランド差し色、`<link rel="icon">`とヘッダーにロゴ。実装例: RINCLEリポジトリ `documents/98_presentations/index.html`

## 検証（ページを書いたら必ず）

python3で: html.parserのパース、`<div>`開閉数一致、旧様式の残存ゼロ（旧パステル配色 #F95320/#23201D 系の直書き・ピル型タブ・絵文字アイコン）、ロゴ相対パスの実在。タブページはdata-targetと.tab-panel idの完全一致も確認。
