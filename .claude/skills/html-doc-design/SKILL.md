# HTML資料デザインシステム — 誌面エディトリアル

クライアント向けHTML資料のフォーマット。雑誌の誌面のように、**罫線と余白で組み、明朝の見出しで読ませる**。どの案件でもこの構成・部品で組み、**ブランドカラーだけ案件ごとに差し替える**。

- 見た目の正本は同フォルダの **gallery.html**（全部品の見本。template.css/parts.cssをlink参照しており自動で追随）
- 部品のHTML雛形は **snippets.html**、CSSの実体は **template.css**（資料部品の核）+ **parts.css**（拡張）
- **parts.cssの中身はUI部品**（ボタン・入力欄・モーダル・かんばん等）。資料の中で画面UIを見せる時だけ使う。**納品ページにコピーするのは通常template.cssだけ**で、parts.cssはUI部品を使った時のみ足す（この2ファイルに重複定義はない）
- 規約を「なぜそう決めたか」の経緯・日付つきの教訓は **decisions.md**（判断に迷った時・変えたくなった時に読む。普段は不要）

**部品や規約を追加・変更したら必ず5点セットで更新すること**: ①template.css（実体）②snippets.html（雛形）③gallery.html（見本）④SKILL.md（部品リスト・原則）⑤lint.py（機械チェックできる規約の場合のみ）。CSSだけ直して雛形・見本を忘れるのが典型的な漏れ方（→decisions.md 2026-08-26/09-01）。

## 原則

1. **自己完結**: 納品ページのCSSは`<style>`にインライン（または同一リポジトリ内の共有CSS）。外部CSS/JS/CDN・画像CDNは使わない。**唯一の例外はGoogle Fonts** — 見出し=Shippori Mincho（明朝）・本文=Noto Sans JPを`<link>`で読み込む（snippets.html冒頭）。フォールバックにシステムフォントを並べ、オフラインでも読めるようにする。和文は`palt`、表は`tabular-nums`
2. **ブランドカラーは「焦がしトーン」に落として差し色に**: 案件のロゴ/ファビコンから実測した原色をそのまま使わず、彩度を落とし暗めに寄せた editorial トーンを `--accent` にする（例: 原色#F95320 → 焦がし#B8532F）。中間色（--paper/--ink/--line）はブランドの色温度に寄せる。役割色も彩度低め: 承認の緑#3E6B4F・警告の紅#A8323E・補足の藍#3B5B84・お金の琥珀#C99A2E
3. **罫線と余白で組む・影と塗りは使わない**: 面の区切りは1pxの罫線（強#DCD3C8/弱#E5DDD2）と余白。カードは白面+罫線のみ。**影は浮かぶ部品（メニュー・モーダル・トースト・スライドの額）だけ**。濃い塗りは「まとめ帯（墨）」と「コード面」だけ。**沈めるのに`opacity`を使わない** — 文字色と罫線をグレーに落として沈める（`tr.muted`・`.option.dim`。面ごと薄くすると紙の白が濁る）。**セクション内の部品はコンテナ幅いっぱいに使う** — 用語解説・手順・対比・図解などに個別のmax-widthを付けて右側を空けない（例外は投影用の`.slide`の額のみ。→decisions.md 2026-08-25）
4. **見出しは明朝・数字も明朝の英数字**: 見出し・項目名・数字の見せ場はShippori Mincho。数字は英数字（漢数字は使わない）。セクション番号は薄い大きな明朝数字（rgba墨8%）を見出しの左に敷く。**見出しの階段は4段で固定**: H1=52px（ページ題）/ H2=30px+薄い大数字+キッカー（章）/ 19px=中見出し（素=h3・テーマの区切りにはキッカーを着せる=.sub-item の2形態のみ）/ h4=16px（小見出し）。**これ以上パターンを増やさない**。狭い幅ではH1だけ落とす — 画面幅1100px以下で44px・760px以下で32px（SPAシェルのiframe内で本文幅が約1020pxになり、52pxのままだと題が2行に折れるため。template.cssのメディアクエリが持つのでHTML側でfont-sizeを直書きしない）
5. **正本の明記**: mdが正本の場合、footerは**「正本: <mdパス>」だけ**にする。「md更新時はこのHTMLも同期すること」のような保守者向けの指示は読者に不要なので、footer直前のHTMLコメント（`<!-- md更新時はこのHTMLも同期すること（正本: path/to/source.md） -->`）に置く。同じ理由で、タスク番号（#44等）・スクリプト名・更新の経緯も本文でなくコメントへ（→decisions.md 2026-09-04）
6. **平易な日本語**: カタカナ専門用語は日常語に開く。専門用語は`.term`部品でその場で解説。
   **文章規約**（lintが機械チェック）: ①括弧は全角（）。半角()は英語まわりでも禁止 ②スラッシュは半角/で前後に半角スペース（全角／禁止。例:「訪問2回 / オンライン2回」） ③接続助詞「〜し、/〜り、/〜て、/〜が、」で文をつながない — 句点で切って2文にするか、読点を落として直結する（「ただし、」等の接続詞・慣用句と主語の「〜が、」は対象外）。
   **敬語規約**: 主体で使い分ける — 当社（書き手）の動作=謙譲語（いたします・進めてまいります）/相手の動作=尊敬語（ご契約ください）/中立の事実（〜が決まります）=丁寧語のままにして過剰敬語にしない。表のセル内は言い切り形（〜する）で統一し、敬体は本文・注記だけ。禁止: 提案側の「で結構です」（→「お時間をいただければ十分です」）/二重敬語「ご〜される」（→「ご決裁いただく方」。この2つはlintが拾う）/自称の「こちら」（→「当社」）/客の口語の引き写し（「毎週来てほしい場合」→「毎週の訪問をご希望の場合」）。誤読する語形は避ける: 「洗い出せ、」は命令形に読める（→「洗い出すことができ」）、「間は」は「かん」と読める（→「その間は」）
7. **数字には出典**: 実測値は日付つきで書く。ヒーローに統計チップは置かない
8. **アイコンはSVGスプライト**: 絵文字・文字記号は使わず、snippets.htmlの12種スプライトを`<use>`で参照（線幅1.5）
9. **演出は3点セット**: 読み進みバー・セクションのふわっと表示・章ナビ現在地ハイライト（snippets.htmlのスクリプト。JS無効/アニメ抑制設定でも壊れない）
10. **チャート**: 出典のある数字のみ・1ページ1〜2個。ドーナツは線2.4の細リング・**中央は大きな数字だけ**（単位・出典は凡例側。2カラムの片側など半分幅に置く時は`.chart.compact`）。データ色は 焦がしブランド→墨→下地 の3段まで。**前月比較などの2値比較は横棒ペア`.bars`**（値は明朝で棒の右）。**時間の色は役割色と同格の規約: 濃=当月（焦がし）/ 淡=前月（下地#EAE2D6）** — bars・ファネルのゴースト等、時間比較はすべてこの2色で統一する。**全体の中身の内訳は100%積み上げバー`.stackbar`**（s1=焦がし〈主役〉→s2=墨→s3=下地→s4=罫線色。2本並べて対比を語れる）。**単系列の量比べ・ヒストグラムは`.hbar`**（主役でない棒は`.fill.dim`で沈め、攻めどころだけ焦がし）。**都道府県別の分布は地域タイルマップ`.tilemap`**（正方形タイルの日本列島・色の濃さ6段階=量。面の広がりを見せる図で、正確な比較は`.hbar`を右に併置。47タイルの配置はsnippets.htmlが正）。「1ページ1〜2個」は読み物の資料の目安で、**数字が主役の月次レポートは章ごとに1〜2個まで可**。KPIの見せ場は`.stat-row`。**statの順序は全変種で「ラベルが上」**（数字→ラベル順は禁止。→decisions.md 2026-08-26）。**単価・内訳など「答えでない数字」は中サイズ`.n.md`（30px）に落とす** — 数字の大きさで序列をつける（→decisions.md 2026-09-01）
11. **図には主張を書く**: 図の部品（`.lanes`/`.swim`/`.pflow`/`.funnel`/`.tilemap`/`.stackbar`/`.hbar`/`.bars`/`.chart`/`.phases`）は`<figure class="fig" aria-label="この図が言っていること">`で包む。aria-labelには**図の見た目の説明でなく、読者に持ち帰ってほしい結論を1文で**書く（○「自転車が84%を占め、静的ページは1%に満たない」/ ×「内訳の帯グラフ」）。読み上げソフトへの対応であると同時に、**1文で書けない図は置く理由がない**ことに書く段階で気づける（→decisions.md 2026-09-04）。読者に見せる解説は従来どおり図の直下の読み方ボックス（`.alert.alert-blue`）で、主張はHTMLの中だけに書く
12. **図解の役割色は固定**: ユーザー=藍/店舗(相手方)=緑/**第3の人間役割=墨`.other`**（人間が3者いる図で使う。お金の琥珀・例外の紅を人間役割に流用しない）/システム=焦がしブランド/お金=琥珀/例外=紅。凡例を図の直下に必ず置く。
    **図の使い分け**: 複数の役割がやり取りする流れ（決済・承認等）=**レーン格子`.lanes`**（縦=役割・横=時系列。「お金の動き」行は琥珀・例外の列はピンク面+破線）/ほぼ単役割の直線フロー（認証・検索等）=**箱矢印`.swim`**/図の下で手順を詳しく語る=**役割つき縦フロー`.pflow`**（番号丸=役割色の輪郭+明朝数字・役割キッカー・左罫の注記）/状態遷移=`.swim`の応用（状態=チップ・到達点=hot・離脱=例外の枝）/段階ごとの絞り込み=**ファネル`.funnel`**（棒の幅=構成比・段間に転換率。集計単位が変わる境目の率は「参考」と明記。**前月比較は当月バーの真下に淡色ゴースト`.frow.ghost`+率に「（前月 n%）」併記**。段名が長い資料は**ラベル列型`.funnel.labeled`**で段名を左の固定列へ）。
    **`.swim`型の規格**: ノード=ニュートラルなピル型チップ（白面+1px罫・角丸999px。役割は行ラベルが示すのでノードに色は付けない）・判定=墨罫+太字・強調=焦がし輪郭+薄い面・エラー=紅の破線・矢印は文字でなく線+矢じり（`.swim-arrow`）・分岐は左レール+色つきキッカーラベル。役割間の位置合わせに固定px幅の空白divを使うのは禁止（崩れの元 — レーン格子に置き換える）

## ページ構造

1. **hero（全ページ同一・全幅）** — 紙の背景に、上枠（ロゴ+キッカー｜資料番号・墨の下罫線）→ 明朝の大見出し → リード → メタ行。角丸カード型ヒーローは禁止。リード文は絞らない（幅制限を付けない）。**ロゴは任意**: 案件にロゴが無ければ置かない（代替のモノグラムを発明しない）。有無は全ページで統一（lintが混在を検出）
2. **章ナビ（必須）** — ヒーロー直下に-64pxで重ねる罫線グリッドの索引（明朝番号+章名+一言）。「何もなし」禁止。通常ページ=`.flow`（アンカー）、タブページ=`.flow-tabs`（同じ見た目でパネル切替）。ピル型タブ禁止。最大8個（4列×2行）。項目数が4の倍数でなくても罫線は途切れない（template.cssの::after+:has()が空きマスを自動で埋める仕組み。消さないこと）。サマリーカードをヒーローに重ねない・章ナビや結論と重複する要点カード列を置かない
3. **結論の章（01章・必須）** — 開いて30秒でそのページの答えに当たれるようにする。**答えは章の外の箱に置かず、最初の章そのものにする**（2026-09-04改定。旧`aside`の専用部品は廃止 → decisions.md 2026-09-04）。章ナビの1番目に「1 結論」、本文の最初の`.section`（`id="conclusion"`）の`.section-num`を「01」・h2を「結論」にし、sh-subにそのページの答えの角度を1行（本文から起こす。事実を新しく作らない）。薄い大数字+明朝見出しという**章の文法**は、注記のアラートとも章ナビの格子とも形が違い、章ナビにも載る。**タブ式のページはタブ1を「結論」にする**（`.tab-panel#panel-conclusion`を`active`の初期状態に）。
   **中身は答えの性格で選ぶ**: 数字が答え=`.stat-row` / 判断を求める資料=`table.qa`（左=問い`td.label.wrap`・右=答えで、答えの1文目を`<strong>`で言い切る）/ 一言で足りる=本文1段落。緑のアラート（決定事項）を1枚だけ添えるのは可。**補足**（あわせて読む資料・この資料の読み方・進み具合）は**その章の中の`ul.notes`**に※で1〜2行 — 箱やアラートを重ねない。答えを末尾の`.recap`や5章目に置かない。
   **章の数は8が上限**（章ナビと同じ）。超えるページは答えに近い既存の章（概要・まとめ・比較）と統合して章数を増やさない。**章番号を振り直したら本文中の章参照も必ず追従する**（「05 優先順位」「（5章）」「3章」「タブ4」など）。`id`は変えない（他ページからのリンクを壊さない）。**結論を持たないページ（用語集・APIリファレンス等）は無理に作らない**
4. **section** — 薄い大番号（.section-num）+明朝h2+キッカーのサブ見出し。**章の背景は白⇄紙の交互**（最初の章=白・画面幅いっぱいに染み出す）で章変わりを見せる
5. **部品** — card / term（対になる用語2〜3個は`.term-row`で横並び） / **小見出し分節.sub-item**（章の中のテーマを「焦がしキッカー.kick+明朝19px見出し」の2段で分ける。キッカーは省略可。h4の平坦な連なりは読みにくいが、白面カードで囲うのも不可 — 用語解説と紛れる） / **alert**（**色は3種で固定**: 緑=結論・決定 / 藍=読み方・補足 / 紅=リスク・注意。**琥珀〈黄〉のalertは作らない** — 琥珀は「お金」の役割色で意味が二重になる。「課題・やり残し」は`ul.notes`の※か`.compare-box.bad`へ。1話題1枚・2行以内） / compare-box（○×は`.good/.bad`+`.cb-mark`・**現状/あるべき姿の対比は`.asis/.tobe`**〈マーク不要・tobe=焦がし枠〉） / **選択肢と採否`.options`/`.option`**（検討した案を横に並べ、採用=`.chosen`〈焦がしの枠〉・不採用=`.dim`〈文字と罫線をグレーに落として沈める〉。結論は既存のバッジ語彙`.badge.good`〈採用〉/`.plain`〈対抗案〉/`.muted`〈不採用〉で示し、記号丸に案ごとの色は付けない） / table（上罫墨2px・項目名明朝・数値列は td.num/th.num で右揃え。**当月/前月/増減の比較表は`.table-mom`**: グループ見出し行`.tgroup`・当月=墨・前月=グレー・増減=緑/紅の意味色〈増えたら悪い指標は色を反転〉。**率（%）の前月比は%変化でなく「pt差」（-13pt等）・順位は「位の差」（-0.3等）で見せる** — %の%変化は直感的でない。差は表示値（丸め後）どうしで計算する〈生値の差だと表示と1ptずれて検算で引っかかる〉。**親行の変種は`td.label.ind`でぶら下げる** — 全角空白の字下げ直書き禁止。長い項目名は`td.label.wrap`。主ラベルに原語・補足を薄く添えるのは`span.label-sub`〈例: 他サイト経由 Referral — 平易な日本語を主・専門用語を副で併記〉。項目名の下の1行補足は`td .td-sub`〈2行を超えるなら.termへ〉。**数値列が複数ある表は役割で色を分ける** — 差し色は「答えの金額」列だけ・回数等=`td.num.cnt`〈墨〉・計算の途中経過=`td.num.calc`〈グレー小さめ〉。推奨・標準列は`th.std / td.std`の薄い面〈面を着せるのは1列だけ〉。**関連する列は2段ヘッダーで束ねる** — 1行目にグループ名`th.th-grp[colspan]`〈中央揃え・弱い罫〉+グループ外の列は`th[rowspan=2]`、2行目にグループ内の列見出し〈体制表・料金表の定番〉。**選択肢を横に並べる比較表では選択肢ごとをグループにし、推奨は`th.th-grp.std`+配下の`td.std`で面を着せる〈面は1グループだけ〉**。停止中・対象外の行は`tr.muted`で沈める〈色ベタのハイライトは使わない — 強調は焦がしの太字か`td.std`の薄い面で〉） / codeblock / **開発者向け詳細`.dev-detail`**（`<details>`の折りたたみ。非エンジニア向けの本文と、開発者向けの詳細〈コード・API名・内部仕様〉を同じ場所で分ける。中身は`.dd-body`で包む・小見出しはh5で本文の階段には数えない） / **APIメソッドバッジ`.method`**（`.get`=緑 / `.post`=藍 / `.put`=琥珀 / `.delete`=紅。等幅・白面+役割色の輪郭。**ドット記法で統一**し`.method-get`のハイフン記法は作らない） / ol.steps / ul.notes / **badge**（ink=強調 / brand=最重要 / good=実測 / plain=中立 / 7. **footer** — 罫線+正本パスだけ（原則5）

## 情報の性格 → 部品の選択（迷ったらここ）

書きたい情報の性格から部品を選ぶ。**同じ情報を2つの部品に重複して書かない**。

| 書きたい情報 | 使う部品 | 使わないもの |
|---|---|---|
| そのページの答え・決まったこと | **01章「結論」**（最初の`.section#conclusion`。数字が答え=`.stat-row`／判断を求める資料=`table.qa`の問い→答え／一言で足りる=本文1段落） | 章の外の箱に置かない・アラートを流用しない・末尾の`.recap`に答えを初出させない |

| これから起こりうる悪いこと（リスク） | `.alert.alert-red` | 「課題」と混ぜない |
| 専門用語・指標の定義（読者が初見の言葉） | `.term`（2〜3個セットは`.term-row`で表の直下に） | ※注記に埋めない |

| 数字の見せ場（今月の答え） | `.stat-row`（特大）／答えでない数字は`.n.md` | 表の1行に埋めない |
| 都道府県別の分布 | `.tilemap`（面の広がり）+ 上位の`.hbar`（順位）を併置 | 地図単体で大小を語らない |

| 全指標の網羅 | `.table-mom` | statを10個並べない |
| 良し悪しの対比 | `.compare-box.bad/.good`（×○マーク付き） | |

| 検討した案の採否（決定の記録） | `.options`/`.option`（採用=`.chosen`・不採用=`.dim`・結論は`.badge`） | 3案以上を`.compare-box`に押し込まない・沈めるのに`opacity`を使わない |
| 開発者向けの詳細（コード・API名・内部仕様） | `.dev-detail`（`<details>`の折りたたみ・中身は`.dd-body`） | 非エンジニア向けの本文に混ぜない |

| APIのメソッド（GET / POST 等） | `.method.get`/`.post`/`.put`/`.delete` | `.method-get`のハイフン記法を作らない |
| 手順（読者が実行する） | `ol.steps` | 文章に埋めない |
| 末尾のまとめ | `.recap`（墨帯） | **所見・結論の章が既にあるページには重ねない**（要約の二度手前になる） |
| 前後の文脈に合わせる | 直前の図表と**同じ族の部品**を選ぶ（表の下の補足は表系・図の下の補足は読み方ボックス） | 章の中で部品の族を頻繁に切り替えない |

CSSは `template.css` をそのままコピー（トークンだけ案件ブランドに差し替え）。UI部品（ボタン・入力欄・モーダル等）を資料内で見せる時だけ `parts.css` の該当部品も足す。部品のHTML雛形は `snippets.html`。

## スライド（16:9・打合せでそのまま映す）

`.slide` の型7種: 表紙 / 章とびら（薄い大番号） / 1メッセージ / ビッグナンバー / 2分割（主張+根拠） / ×○比較 / 締め（やること・担当・期日の3列表）。共通規格: 下枠は左=ブランド名・右=ページ番号（表紙のみ日付）、1枚に言いたいことは1つ、表は5行まで、本文の最小は投影で読める18px相当。

## 長いページはタブ化

縦に長いページ（画面5〜6枚分超）は章ナビ型タブで章を切り替える: `.flow-tabs`+`.tab-btn`(fnum/ft/fd)+`.tab-panel`+切替script（snippets.html）。ハッシュ更新で直リンク可。ページ内アンカーが多いページはタブ化しない。

## 複数ページをまとめるSPAシェル

資料が複数ある案件は index.html（サイドバー+iframe方式）でまとめる: **雛形は同フォルダの `shell.html` をコピー**し、`<title>`・sidebar-header・`pages`配列・`--shell-*`ブランドトークンだけ差し替える。アコーディオン式セクション（件数バッジ）・**ようこそ画面**（資料集の一言 → 「まず読む3本」の罫線グリッド〈章ナビと同じ組み〉→ セクションごとの1行説明の目次。`welcome`オブジェクトと`sectionNotes`に文言を書くだけで組み上がる。`AUTO_OPEN_FIRST`が`false`の時に出る＝既定）・ハッシュ直リンク復元・**iframe内リンク追従**（ページ内の相互リンクで遷移してもサイドバー現在地とハッシュが同期する）を備える。favicon・ロゴは任意（ロゴ無し案件は省略。モノグラムを発明しない）。

## 検証（ページを書いたら必ず）

**同梱の `lint.py` を実行する**: `python3 <このスキルのフォルダ>/lint.py <出力ディレクトリ>`（固有名詞の絵文字は `--allow-emoji "🥑"` で許可、資料集は `--multi-doc`）。指摘ありはexit 1。**チェック項目の一覧は lint.py 冒頭のdocstringが正**（構造・統一性・章ナビ・部品規約・残骸・文章・敬語。ここに列挙を複製しない — 二重管理で必ずずれる）。gallery.html のような部品カタログは冒頭の `<!-- lint-mode: specimen -->` 宣言で文脈依存チェックだけ免除される。

**複数エージェントに生成を並列分担させた後は必ず全ファイルにかける**（並列作業の参照割れは構造検証では出ない。→decisions.md 2026-08-26）。lint.pyで拾えない項目は目視で: 章の背景交互、図解の役割色と凡例、リンク先の実在。

**初見レビュー（節目だけ）**: 構成を大きく変えた時・新しい種類の資料の初回・大きな主張を載せる時は、資料を初めて見るエージェントに「分かりにくいデザイン / もっと良い見せ方」を拾わせる。道具は `review/`（撮影スクリプト shoot.mjs・依頼文 prompt.md・手順 README.md）。毎月はやらない（1回約20万トークン。→decisions.md 2026-09-02）。
