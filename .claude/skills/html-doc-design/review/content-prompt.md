# 内容レビュー（フレッシュアイ）— 依頼文

作った本人には見えないもの（不自然な日本語、論理の飛び、見出しと図の食い違い、根拠のない評価語、既出の焼き直し、数値の不整合）を、**文脈を共有しない別のエージェント**に読ませて拾う。デザインの初見レビュー（`prompt.md`・撮影が要る・約19万トークン）とは別物で、こちらはHTMLを読ませるだけなので**納品のたびに回せる**。

出典: carnot-tech/consulting-pptx-skill の `references/content-review-prompt.md`（MIT）をHTML資料向けに読み替えたもの（2026-09-25）。

## 使い方

1. 機械チェック（lint.py）が ALL CLEAN のあと、納品前に回す。
2. 下の指示文の `{FILE}` `{READER}` `{OUT}` を埋め、**作り方・使ったスキル・こだわった点を一切伝えずに**、general-purpose のエージェント（fork不可・初見が価値）に渡す。1ファイル1エージェントで並列に走らせてよい。
3. 返ってきた指摘を**採否表**にする。全部直すのではなく1件ずつ「採用／不採用／保留」を決める。意味が変わる言い換えや構成の組み替えは依頼者に見せて決めてもらう。
4. 採用分を直し、lint.py を再実行する。不採用は理由を1行残す。
5. 「機械チェック → 目視 → 内容レビュー → 採否表 → 採用分の修正 → 機械チェック再実行」を**1ラリー**と数える。**1ラリー終えたら止めて、成果物と採否表を見せたうえで次を聞く。** 頼まれていないのに2ラリー目を自走しない。着手時に速度優先（内容レビューなし）／標準（1ラリー）／品質優先（指定回数）を決めておく。
6. 規約にすべき指摘は decisions.md に経緯を、SKILL.md に規約を1行追記する（指摘を1行ずつ蓄積する運用）。

### 採否表の形式

| # | 章 | 指摘（原文のまま） | 種別 | 採否 | 対応／理由 |
|---|---|---|---|---|---|
| 1 | 03章 | 「追いついた」は完了形で不自然 | 日本語 | 採用 | 「追いついている」に修正 |
| 2 | 02章 | 前提の表から帰結が導けていない | 論理 | 採用 | 章副題を主張文に |
| 3 | 04章 | 「主要な」は曖昧 | 日本語 | 不採用 | 直後の表で列挙している |

種別は「日本語」「論理」「破綻（数・図・数値）」「体裁」の4つ。

## 指示文（ここからコピー）

あなたは業務資料のレビュアーです。1本のHTML資料を読み、**作った本人には見えない破綻**を指摘してください。どう作られたかは知らされません。推測して書く必要もありません。

### 見る対象
ファイル `{FILE}`。**Readでファイル全体を読み、章を順に確認してください。** 一部だけ読んで推測しないこと。他のファイル（規約・スキル・テンプレート・同じフォルダの別資料）は読まないでください。あなた自身の判断で採点します。

読者: {READER}。読者が開いて30秒で「何の話か・何を判断すればいいか」を掴めるか、その後迷わず読み進められるかが価値のすべてです。

資料の構造: 先頭に題と導入文（hero）、章の索引（flow または flow-tabs）、続いて各章（section）。各章は「章番号＋見出し（h2）＋章副題（sh-sub）」で始まり、表・図・箇条書き・注記（notes）が続きます。図は `<figure aria-label="…">` で包まれ、aria-label にその図の主張が書かれています。

### まず確認する2点（章名付きで報告）
- **日本語の言い回し**: 日本語話者が読んで引っかかる表現をすべて挙げる。完了形と進行形の取り違え、口語、主語や述語が抜けた圧縮語（「手動作成」「精度向上」）、同じ語尾が揃っていない箇条書き、名詞に畳み込んで読めなくなった長い修飾、定義なしの略語・造語、同じ概念の表記ゆれ。**内容が正しくても日本語が不自然なら指摘する。**
- **論理展開**: 各章の「見出し＋章副題」だけを上から通し読みして、話が飛ぶ・戻る・同じことを二度言う・前提なしに結論が出る箇所を挙げる。章の中では、章副題が本文から導けるか、表や図の主張（aria-label）と本文が一致しているか、比較の基準（何と何の比か）が明示されているか。

### 必ず確認する破綻（章名付きで報告）
1. **見出し・副題の数と本文の数の食い違い**: 「3つの手」と書いた章に項目が4つ、など
2. **見出しと図表の結論の食い違い**: 見出しや章副題で限定・否定していることを、同じ章の図や表で断定している
3. **裏づけのない評価語**: 「限定的」「十分」「問題ない」「最小限」「安全」などの評価語が、その章内に根拠なく置かれている
4. **既出の焼き直し**: 後半の章が前半の内容をほぼ繰り返しており、新しい論点を足していない
5. **索引・結論と本編のずれ**: 章の索引や01章の結論で予告した論点・章参照（「（4章）」等）と、実際の本編が一致しない
6. **数値の不整合**: 同じ量が別の章で違う値になっている、合計が合わない、単位・期間が途中で変わる、日付と曜日が合わない
7. **出典・注記の欠落**: 数値を載せた箇所に出所がない。仮置き・試算・未確認の断りが必要な箇所に無い

### 採点軸（各10点・合計70点）
1. ストーリーの通り: 見出し＋章副題だけを上から通し読みして、1本の主張として成立するか
2. 1章1メッセージ: 各章の主張が明確か。詰め込みすぎ・薄すぎがないか
3. 情報の構造: 比較・因果・並列が適切な形（表・図・箇条書き）で表現されているか。表向きのデータが文章で済まされていないか
4. 読みやすさ: 文の長さ・段落の区切り・注記の量が読者に合っているか
5. 説得力: 読者が判断・反論・行動するときに、そのまま使える形になっているか
6. 一貫性: 全章で用語・ラベル・日付の書き方が揃っているか
7. 誠実さ: 数値の出所・限界・未確認の断り方が適切か。読者を誤認させないか

### 出力
`{OUT}` にMarkdownで書く。構成:
1. 日本語の言い回し・論理展開の指摘を、**章名・該当箇所の引用・何が問題か・言い換え案**の4点で列挙する（多くてよい。10件以上でも構わない）
2. 破綻1〜7の該当箇所を、**章名・該当箇所の引用・何が食い違っているか**の3点で列挙する。該当なしの項目は「該当なし」と書く
3. 軸ごとの点数と、その理由を各1〜2文
4. 合計点
5. **直すべき順に並べた指摘リスト（上位5件）**。各1〜2文で「どう直すか」まで書く

盛らずに書いてください。欠点を最低3つ挙げてください。無傷の資料はありません。ファイルの編集は一切しないこと。最後に、レポートのパスと上位5件だけを簡潔に報告してください。
